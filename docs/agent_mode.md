# AGENT 模式（实验性功能）

本文档说明 NarrChat 的 AGENT 模式（「设置 → 通用设置 → 实验性设置」开关，
**默认关闭**）：模式与平台接入协议**全解耦**——协议只决定线路格式（见下文
「模式与协议」），本开关启用两阶段生成流程、上下文构成、锚定式状态工具与
已知限制。工具级细节见 `docs/agent_tools.md`。

## 模式与协议（全解耦）

设置 →「API 设置」中每个平台一个**接入协议**——**协议只决定请求体 / 线路
格式**，不再自动启用 AGENT 模式。AGENT 模式是「设置 → 通用设置 →
**实验性设置** → **Agent 模式**」中的独立开关（**默认关闭**）：描述中声明
会调用自定义工具（`narrchat_readState` / `narrchat_editSection` /
`narrchat_webSearch` / `narrchat_webFetchPage`）、使用两阶段生成 /
`tool_choice` / `previous_response_id` 链式续接 / 状态工作副本合并等
特性，并明确说明可能导致错误、兼容性与正确性不保证、可能不被服务商支持。

| 协议 \\ Agent 开关 | 关（默认） | 开 |
|---|---|---|
| OpenAI Chat API 兼容 | 传统 Chat 对话（6 区块输出 + 可选联网搜索循环），`POST {baseUrl}/chat/completions` | AGENT 两阶段在 Chat 通道运行（帧转为 `tool_calls` / `role: tool` 消息；无 `previous_response_id`，每帧全量重发） |
| OpenAI Response API 兼容 | 纯文本单轮（instructions + input，无工具 / 状态机制）；联网搜索为 Responses 工具循环，`POST {baseUrl}/responses` | AGENT 两阶段（行级状态工具 + 工作副本；有状态平台可开启链式续接） |

内置默认平台与自定义平台的「API 类型」下拉均可实时切换（保存后立即生效，
无需重建平台）；「自定义请求体模板」功能已移除（未来以独立于兼容的高级
自定义另行设计）。

## 核心设计：正文与状态分两阶段

旧版把「写正文」和「维护四个状态字段」塞进同一次响应，模型既要自由写作
又要逐条调工具，稳定性差（正文重复输出、状态漏项）。现在按阶段拆开：

| | 阶段 A：正文轮 | 阶段 B：状态轮 |
|---|---|---|
| 是否必发 | 是 | **仅当**存在缺口 / 失败的编辑（正文轮把状态补齐时**零额外请求**） |
| `tool_choice` | `auto`（可省，见降级） | `required` |
| 帧数上限 | `kAgentMaxStoryFrames` = 8（联网搜索要吃多帧） | `kAgentMaxStateFrames` = 3 |
| 文本通道 | 门控后上屏（开场白不可见） | **完全关闭**（一律丢弃，不上屏也不落库） |
| `max_output_tokens` | 用户设置值 | **同左，一律不改**（程序不为状态帧擅自抬高上限） |
| 思考（reasoning） | 用户设置值 | 用户开启时**降为 `low`**（不硬关：状态维护需要理解正文与快照；`low` 同时省预算） |

阶段 B 输出的是工具参数 JSON（逐字中文锚点 + 多条 edits），沿用正文的输出上限
容易被截断；补救手段是**思考降为 `low`（用户开启时）+ 要求模型拆短调用 +
提示用户调高设置**，而不是在程序里改写用户设定的 `max_output_tokens`。

### 截断（`response.incomplete`）怎么处理

输出触顶时服务商发的是 `response.incomplete`（**没有** `error` 字段，只有
`incomplete_details.reason`）。旧实现把它和 `response.failed` 合并抛异常，
文案恒为「**API 请求中断：null**」，还会连带赔掉本轮已生成的正文。现在：

- 底层（`AiService.responses`）：保留截断前的正文与工具参数，标记
  `AiCallResult.incomplete` + `incompleteReason`，**正常返回不抛异常**；
  `failed` 仍抛，但文案兜底为「服务端未给出原因」，绝不出现 `null`；
- 执行器：给下一帧补一条「减少并拆短工具调用（一个栏目一次调用、edits 尽量
  少、不要复制长段文本）」的指令；截断的响应**不作为续接基点**（下一帧全量重发）；
- **不改请求体的 `max_output_tokens`**：两阶段都按用户设置原样发送，
  触顶属于用户可自行调节的参数，程序只提示不擅改；
- 末帧仍被截断 → 常驻黄框首行给出可操作提示（去设置里调高「最大 token」）；
  正文一帧都没产出时，失败条目的黄框与红框也会写明「被输出上限截断」。

### 一轮的完整流程（`AgentRoundRunner`）

1. **组装**：`instructions`（`PromptMode.agent`）+ 历史消息（**只有正文三小节**）
   + 当前用户消息；**不预置任何快照**——状态由模型主动调用
   `narrchat_readState` 获取。工具集 = 读取器 + 状态编辑器恒定注册，
   联网搜索开启时叠加搜索 / 打开页工具。
2. **阶段 A（正文轮，`tool_choice=auto`）**：契约要求**先调用
   `narrchat_readState`**（返回 = 上一轮库内状态，正文写什么必须以此为准），
   再产出三个小节：`## 剧情演绎` → `## 推荐行动` → `## 当前时间`
   （当前时间属于**正文**，不设时间工具；应用从正文解析写入工作副本）。
   `narrchat_editSection` 在正文轮**禁止**（违规仍执行兼容，但正确性不依赖）。
   退出条件：本帧无工具调用；或**已采纳标题正文且本帧工具全是状态编辑工具**
   （补齐与否交给阶段 B）。含搜索 / 打开页 / 读取器等**喂正文**的工具时继续
   下一帧（结果必须回到上下文）。
3. **缺口判定**（`state_coverage.dart`，纯应用侧事实，不采信模型自述）：
   见下表（时间不参与判定）。有缺口或阶段 A 有失败的编辑 → 进入阶段 B。
4. **阶段 B（状态轮，`tool_choice=required`）**：指令要求**先调用
   `narrchat_readState`**（返回 = 上一轮 + **本轮正文之后**的状态，锚点唯一
   正确来源；其中 `<time>` 块是正文时间，**不可编辑**），再按
   `[State-maintenance turn]` 指令（EN 行 + 【中】行）列出的待修各项
   （至多 8 条）逐栏目 `narrchat_editSection`。**优先级：记忆 → 角色 → 世界**
   ——一次响应尽量完成全部清单；装不下时先做记忆与角色（每轮记忆是硬义务）。
   修复帧**不重读**——复用上一帧快照与失败回传的「栏目当前全文」。
   状态帧「空手帧」（只回文本/只回读取器）**不会提前结束**状态轮：
   只要清单还有缺项就继续修复，帧数上限（1 主 + 3 修）兜底。
5. **落库**：工作副本快照合并进本轮 `Round`（每轮仍存全量快照六字段，
   侧边栏可编辑、云同步与历史结构零改动）。**不再有「文本状态兜底」**——
   状态只能经工具落地，正文里违规出现的世界/角色/记忆区块**剥离后**才写入
   正文（`## 当前时间` 是合法正文段，直接落库）。
6. **警告（两级，同一黄框形态）**：
   - 生成期间：流式气泡顶部实时提示本轮已跳过的项；
   - 结束后：**常驻黄框挂在对应轮次的气泡内**（`RoundProvider.roundWarningsFor`），
     内容 = 状态轮用尽后仍存在的缺口 + 终态仍未修复的栏目，右上角 ✕ 可手动关闭；
     **仅存内存**（不入库、不进云同步，跨设备不体现），重生成该轮 / 修改提问 /
     删除该轮时随轮次一起清除，杀进程即清空；
   - 正文为空的 AGENT 轮（模型只返回工具调用）：本轮**不写库**、用户输入走既有
     「失败条目」（可一键重试），并在失败条目下方挂黄框说明「状态改动已作废」。
7. **取消 / 失败**：工作副本整体丢弃，库无半成品（失败条目与 Chat 一致）。

### 缺口判定

| 缺口 | 触发条件 | 状态轮指令 |
|---|---|---|
| `sectionUntouched` | 栏目既没被编辑、也没 `op=noChange` 声明 | 调用一次 `narrchat_editSection` |
| `sectionUnchanged` | 做过编辑但整栏与上一轮逐字节相同（记忆栏除外） | 按最新快照做实际编辑 |
| `lazyCharacters` | 本轮正文出现的具名角色，其 `## 角色名` 块与上一轮逐字节相同 | 逐行 `op=set` 实际编辑；仅纯提及角色允许 `op=noChange` + `reason` |

当前时间**不参与**缺口判定：它属于正文（`## 当前时间` 小节），
缺失时工作副本沿用上一轮时间（正文质量问题，不作状态缺口）。

## 上下文构成（前缀缓存友好）

两个阶段的 `instructions` 与 `tools` **逐字节相同**（阶段 B 不裁剪规则、
不换工具集），历史前缀也相同，只有尾部不同 —— 服务商的 prompt cache 在
阶段 B 与下一轮都能命中：

- **历史里的 assistant 消息只携带三个正文小节**（`PromptBuilder.buildHistoryMessages`
  的 `storyOnly` 参数 + `AiResponseParser.serializeAgentBody`：剧情 / 行动 / 时间）。
  这是稳定性的关键：历史中一旦出现 `## 世界状态` 之类区块，模型就会照抄
  Chat 模式的 6 区块输出。Chat 模式的历史序列化逐字节不变。
- **状态**由模型**主动调用** `narrchat_readState` 获取（**真实注册**的只读
  工具，不预置、app 不伪造条目）：返回值永远是**工作副本当前渲染**
  （正文轮调用 = 上一轮库内状态；状态轮调用 = 正文之后的状态），
  应用侧无需从调用序列区分阶段。结果以 `function_call_output` 形态进入
  上下文——**工具结果，不是输出格式**，不会诱发模型模仿 md 格式把状态
  写进正文（老版本把快照预置成工具输出，模型反而照抄格式）；
  上下文中**只保留最新一份**读取结果（旧份自动剔除，输入不随修复帧膨胀），
  修复帧不重复读取。
- 快照边界内是 `<time>` / `<worldState>` / `<characterState>` /
  `<memorySummary empty="true">` 四段，与 `Round` 的四字段一一对应。

## 协议兼容降级（就地重发同一帧，不烧帧预算）

`_callFrame` 捕获 `AiExceptionKind.api` 的 4xx 类错误，就地降级后重发**同一帧**
（`_frames` 不计数，工具不重复执行；同一帧至多连降 3 项）：

| 症状 | 降级动作 |
|---|---|
| 报错含 `tool_choice` | 本轮之后都不再发送 `tool_choice` |
| 报错含 `previous_response_id` | 本帧改为全量重发 input |
| 报错含 `reasoning` / `thinking` / `effort` | 状态帧不再覆盖思考强度（回落用户设置；工具参数的输出预算相应少一截，只能靠「拆短调用」指令与用户调高「最大 token」补救） |

只有**内容校验失败**（锚点未命中、记忆缺本轮条目等）才消耗修复帧。

## 单轮链式续接（previous_response_id）

默认**关闭**：`previous_response_id` 仅用于“单轮内多次调用”的续接帧，
**永不跨轮**（历史轮次与记忆结构不变，请求体形态跨预算一致）。

- 平台设置 →「允许链式续接（previous_response_id，需服务商支持）」默认关；
- DeepSeek 官方为**无状态 API**（`previous_response_id` / `conversation` /
  `store` 均不支持且静默忽略），关闭时每帧全量重发输入；
- OpenAI 官方等有状态实现可开启：续接帧只发新增输入项（`tools` /
  `instructions` 一并省略）。

## 锚定式编辑（状态栏目）

参考 DeepSeek Harness / Claude 系工具的行级定位机制——**不用行号**（LLM 数行号
不可靠，是「改错行 / 记忆替换第一行」的根源），改为**原文锚点 + 唯一匹配**：

- `narrchat_editSection`：`edits` 只携带**变更的行**；`before` 必须是从快照中
  **逐字复制**的行（可含 `\n` 连接连续多行）。匹配三级递进：逐字行 → 归一化行
  （折叠空白与全/半角标点）→ 归一化行内子串；
  - 未命中 → 报错（提示逐字复制 + 当前行数 + **该栏目当前全文**供重锚，至多 400 行）；
  - 不唯一 → 报错（列出命中行号，引导补充唯一上下文）；
  - 命中 → 只替换该段行，未触及的行字节级保留；
- `op=append` 追加到栏目末尾（记忆条目固定用它）；`set` / `insertAfter` /
  `delete` 均以 `before` 锚定；`op=reset` 仅限空栏目 / 首次填入 / 明确重排；
- `op=noChange` **必须携带非空 `reason`**（省略栏目 ≠ 声明无变化），登记进
  `declaredUnchanged` 供缺口判定放行；记忆总结**不接受** `noChange`；
  noChange 是**最后手段**：正文里角色/局势只要有新动向（一句反应、一段心理、
  一次移动本就是「变化」），就应写一条 `op=set`；一次调用可带**多条** `edits`
  （每条对应一行改动），提示词与工具描述明确点名「无需大改」这类空泛理由会被
  视为懒修改；
- 同一调用内按顺序应用（锚点在应用时刻解析），**事务化**：任一编辑失败整体不提交；
- 结构性校验只有一条：记忆总结变更后必须恰含一条本轮（`第 N 轮`）条目；
- **当前时间不设工具**：属于正文 `## 当前时间` 小节，正文采纳时由应用解析
  写入工作副本（缺失则沿用上一轮时间）；
- 工具结果分两面：`summary`（UI 一行）与 `modelOutput`（回传模型全文，含栏目
  当前全文）；参数被截断（`argumentsUnparsable`）时不执行，回传「一栏目一次
  调用」的重试指引。

## 其它交互

- **正文采纳制（最后一个标题帧胜出）**：本轮正文 = 阶段 A **最后一个**含
  `## 剧情演绎` / `## 正文` 标题的帧的原始内容；无标题 + 带工具的帧是**开场白**
  （「我先搜索一下…」），不上屏、不采纳、不阻塞真正正文；无标题 + 无工具的帧
  按未按格式输出的正文兜底。门控 `_FrameGate` 在每帧正文首次出现前发
  `AiStreamChunk(narrativeReset)`，界面表现为正文块重置重流（不是拼接）；
- **块顺序**：思考 / 搜索 / 打开页 / 状态工具按 **AI 返回顺序**流式展示；
  正文是「块外」特殊块，插入在其返回位置；
- **统一工具块**：联网搜索 / 打开页面 / 状态工具共用同一形态，标题统一为
  `Tool · 工具名`（Chat 模式保留语义化标题）；**一次工具调用只产生一个框**
  （流式预览 / 开始 / 完成共享同一事件，按 callId 匹配）；执行中自动展开明细，
  成功自动收起为一行，失败保持展开完整原因（黄 = 页面拒绝访问，红 = 校验失败）；
- **AGENT 徽标**：Chat 页左下角模式摘要显示 `AGENT`（由实验性开关启用，可随时关闭）；
- **提示词**：契约规则与工具描述均为**中英双语**（英文规则行在前 + 中文一行摘要，
  字面量与标题名永不翻译），提升模型遵循度；
- **联网搜索**：独立开关照旧；AGENT 模式下与状态工具同批注入
  （`narrchat_webSearch` → `narrchat_webFetchPage` → 正文 + 状态工具）；
- **视觉**：AGENT 模式支持图片输入（responses `input_image` 内容块，仅视觉模型）；
- **非流式**：用户选择非流则整轮（含状态轮帧）全非流，由 `NonStreamReplayer`
  回放，同样经过帧门控；
- **RAW**：RAW 对话框 AI 返回区为「思考块 / 工具调用块 / 正文块」，
  每帧一条交换记录（含状态轮帧）；预览请求体 = 响应式首帧 JSON。

## 已知限制

- 常驻黄框只在本次进程内有效（刻意不入库：它属于本机生成过程的诊断信息，
  不该进用户数据与云同步），换设备 / 重启后不再显示；
- 懒修改判定按「角色名在正文中原样出现」字面匹配，别名 / 代称不参与；
- 云同步 / 书籍迁移不感知 AGENT（数据形态与 Chat 完全一致，无迁移要求）。
