# AGENT 模式（实验性功能）

本文档说明 NarrChat 的 AGENT 模式（「设置 → 通用设置 → 实验性设置」中的
**三档下拉：关 / Lv.1 / Lv.2**，默认**关**）：档位与平台接入协议**全解耦**——
协议只决定线路格式（见下文「模式与协议」），档位决定生成流程、上下文构成与工具集。
工具级细节见 `docs/agent_tools.md`。

## 档位总览

| | 关（默认） | **Lv.1** | **Lv.2** |
|---|---|---|---|
| 提示词模式 | `PromptMode.chat` | `PromptMode.agentLv1` | `PromptMode.agentLv2` |
| 正文输出 | 6 个二级标题区块 | **5 个区块**（排除 `## 记忆总结`） | 3 个小节（剧情 / 行动 / 时间） |
| 状态工具（每栏一读一写） | 无 | 仅**历史（记忆总结）** | **世界 / 角色 / 历史**全部 |
| 联网工具 | 用户开关 | **强制开启** | **强制开启** |
| 维护轮 | 无 | **仅记忆未落地 / 有缺口时发起**（合规流程零额外请求） | 有缺口才发（缺口驱动） |
| 历史消息（assistant） | 最新一轮 6 区块，更早仅正文 | 最新一轮 5 区块，更早仅正文 | 每轮 3 小节 |

档位语义的**单一映射**在 `AgentModeProfile`（`lib/services/agent/agent_mode_profile.dart`）：
提示词模式、工具栏目、正文禁用标题、历史消息形态都从它取，各层不再散落档位判断。
新增档位（Lv.3+）只需扩展 `AgentModeLevel` 枚举与 `AgentModeProfile` 两处，
设置页下拉与 Chat 页徽标自动跟随。

## 模式与协议（全解耦）

设置 →「API 设置」中每个平台一个**接入协议**——**协议只决定请求体 / 线路
格式**，不决定档位。档位是「设置 → 通用设置 → **实验性设置** → **Agent 模式**」
中的独立下拉：描述中声明会调用的自定义工具（见下表）、分阶段生成 /
`previous_response_id` 链式续接 / 状态工作副本合并等特性，
以及思考 / 流式 / 搜索在 Agent 期间**强制开启**（可在模型配置页关闭对应能力
以禁用），并明确说明可能导致失败、兼容性与正确性不保证。

| 协议 \\ 档位 | 关（默认） | Lv.1 / Lv.2 |
|---|---|---|
| OpenAI Chat API 兼容 | 传统 Chat 对话（6 区块输出 + 可选联网搜索循环），`POST {baseUrl}/chat/completions` | Agent 分阶段流程在 Chat 通道运行（帧转为 `tool_calls` / `role: tool` 消息；无 `previous_response_id`，每帧全量重发） |
| OpenAI Response API 兼容 | 纯文本单轮（instructions + input，无工具 / 状态机制）；联网搜索为 Responses 工具循环，`POST {baseUrl}/responses` | Agent 分阶段流程（六工具 + 工作副本；有状态平台可开启链式续接） |

内置默认平台与自定义平台的「API 类型」下拉均可实时切换（保存后立即生效，
无需重建平台）；「自定义请求体模板」功能已移除（未来以独立于兼容的高级
自定义另行设计）。

## Chat 页左下角指示器（Agent 专属形态）

- **档位开启（Lv.1 / Lv.2）**：输入框左下角改为**联网同款黄色徽标**，
  文本为 `Agent Lv.1 On (BETA)` / `Agent Lv.2 On (BETA)`（不再显示
  「流式 \| 思考 \| 搜索」摘要）；
- 徽标仍可点开菜单：里面 **思考 / 流式 / 搜索**三行**如实显示用户原本配置**
  但**整行置灰不可点**，并附小字「Agent 模式已强制开启，此处不可关闭」
  （搜索行同时保留 BETA 试验版提示）；**模型配置页关掉的能力不显示该行**；
  「导入图片」入口照旧保留；
- 点开菜单顶部的 AGENT 信息块按当前档位说明契约（Lv.1 = 仅历史工具 + 5 区块；
  Lv.2 = 六工具 + 3 小节）。

### 强制开启的语义（不改写用户设置）

Agent 期间 `思考 / 流式 / 搜索` 一律**按模型能力强制为开**（`supportsThinking` /
`supportsStreaming` / `supportsSearch`，由模型配置页控制）：组合时快照覆盖，
**不写入**用户已保存的 Chat 每轮选项；关闭 Agent 后立即恢复用户原设置。
能力不支持时对应功能自然关闭（搜索工具不注入、思考不强制发送）。

## 核心设计：正文与状态分阶段

旧版把「写正文」和「维护状态字段」塞进同一次响应，模型既要自由写作
又要逐条调工具，稳定性差（正文重复输出、状态漏项）。现在按阶段拆开：
**Lv.1 为三段**（调研 → 记忆 → 正文 → 维护兜底；无联网时恰好 3 次请求），
**Lv.2 维持两阶段**（正文轮 → 缺口驱动的维护轮），执行器阶段枚举为
`AgentStage{prepare, memory, state, story}`：

| | 调研轮（仅 Lv.1） | 记忆轮（仅 Lv.1） | 正文轮 | 维护轮 |
|---|---|---|---|---|
| 是否必发 | **必发** | **必发**（记忆先于正文落地） | 是 | **仅缺口出现时**（Lv.1：记忆未落地 / 校验失败 / 截断；Lv.2：存在缺口 / 失败的编辑——正文轮把状态补齐时**零额外请求**） |
| 帧数上限 | `kAgentMaxPrepFrames` = 6（联网搜索要吃多帧） | `kAgentMaxMemoryFrames` = 3（1 主帧 + 2 次提醒） | `kAgentMaxStoryFrames` = 8（联网搜索要吃多帧） | `kAgentMaxStateFrames` = 4（1 主帧 + 3 修复帧） |
| 文本通道 | **不上屏**（本阶段只备事实依据，不产出大纲 / 正文） | **完全关闭**（一律丢弃，不上屏也不落库） | **唯一上屏阶段**（门控后上屏，开场白不可见） | **完全关闭**（一律丢弃，不上屏也不落库） |
| `max_output_tokens` | 用户设置值 | 用户设置值 | 用户设置值 | **同左，一律不改**（程序不为状态帧擅自抬高上限） |
| 思考（reasoning） | 用户设置值（Agent 期间强制开启） | 用户设置值（Agent 期间强制开启） | 用户设置值（Agent 期间强制开启） | 降为 `low`（不硬关：状态维护需要理解正文与快照；`low` 同时省预算） |

工具调用由**帧指令 + 工具描述**驱动（每帧明确要求本回合直接调用对应编辑器），
**不发送 `tool_choice`**：部分服务商在思考模式下以 400 拒绝该参数
（`Thinking mode does not support this tool_choice`），而阶段语义并不依赖它——
落地与否一律以工作副本事实判定，缺项由维护轮兜底。

维护轮输出的是工具参数 JSON（逐字中文锚点 + 多条 edits），沿用正文的输出上限
容易被截断；补救手段是**思考降为 `low` + 要求模型拆短调用 + 提示用户调高设置**，
而不是在程序里改写用户设定的 `max_output_tokens`。

### Lv.1 的三段流程（调研 → 记忆 → 正文）

Lv.1 的世界状态 / 角色状态随**正文文本**携带（复用 Chat 的区块契约），只有
**历史（记忆总结）**走工具。旧流程「先写正文、再在维护轮补记忆条目」要求模型
写完长正文后再回读总结，既费 token 又容易与正文脱节；现在改为三段：

1. **调研阶段**（`stage=prepare`，**文本零输出**）：先调
   `narrchat_readHistory` **一次**（历史的**唯一来源**；此前的 assistant 消息
   不含记忆区块）；需要现实资料时联网搜索（`narrchat_webSearch` →
   `narrchat_webFetchPage`，可多步）。**本阶段不写大纲、不写记忆、不写正文**：
   它只负责把事实依据（历史锚点 + 现实资料）备齐，模型写什么都一律丢弃
   （因此也不需要在文本通道写进度汇报）。帧上限 `kAgentMaxPrepFrames` = 6
   （联网一次典型 3 帧）。**退出条件**：本帧不再调用工具；或本帧工具**只有
   读取器**（读完历史且没有联网意图 → 直接进入记忆阶段，无联网时全轮恰好
   3 次请求——这一条正是「不再给模型一帧去复述大纲」的关键）。
2. **记忆阶段**（`stage=memory`，**文本通道关闭**）：**同一个回合**内先推演
   剧情（**思考通道**里定下大纲：关键事件 / 出场角色 / 本轮结束时的剧情内时间，
   时间沿用历史格式），再用 `narrchat_editHistory`（`op=append`）追加**恰好一条**
   `- {轮次} | {时间} | {记忆内容}`（{轮次} = 本轮轮号（裸数字）；
   {时间} = 大纲里本轮结束时的剧情内时间；正文的 `## 当前时间` 必须与其一致）。
   「思考剧情」与「落条目」**刻意合并在同一回合**：拆成两回合时，模型会在第一
   回合结尾用文本复述大纲（「准备完成 / 大纲如下 / 下一回合我就…」），既浪费
   输出，又容易把落条目拖到下一回合甚至漏掉。
   若与历史旧条目 / 既有文案的写法冲突，**以新格式为准**（旧条目本身原样继承、
   不改写）。**档位 > 0 且未合并条目达到 2×档位时**，该调用还要把最旧的若干条
   合并为区间条目（见「记忆总结轮次合并」小节：脚本由应用在生成前算定并写进
   本阶段帧指令，完成判定并入 `_memorySatisfied()`）。帧上限
   `kAgentMaxMemoryFrames` = 3。
3. **正文阶段**（`stage=story`，**唯一上屏阶段**）：按大纲 +
   书籍设定 / 文笔参考输出 5 个二级标题区块：`## 剧情演绎` → `## 推荐行动` →
   `## 当前时间` → `## 世界状态` → `## 角色状态`；**禁止**输出 `## 记忆总结`
   （它只以工具结果形式出现；应用侧采纳时仍会剥离）。帧上限
   `kAgentMaxStoryFrames` = 8。
4. **维护轮（兜底）**：不再是「Lv.1 每轮必发」，只在**记忆未落地 / 校验失败 /
   截断**等缺口出现时才发起；合规流程下 Lv.1 **零额外请求**。

为什么记忆条目**先于正文**落地：

- **大纲派生**：条目内容取自记忆阶段思考通道里定下的大纲（关键事件 + 概括），
  不需要模型重读刚生成的长正文再总结，省掉一次长上下文回读；
- **成为正文的约束**：条目先落地后即为正文的**既定约束**，正文的 `## 当前时间`
  与叙事必须与之一致；次序本身也消解了「正文轮先写条目、维护轮再追加」的重复
  条目风险，因此原先「正文轮调用 `narrchat_editHistory` 会被拒绝执行」的护栏
  **已删除**（次序本身已消解重复条目风险）。

落库快照仍是**混合**的：世界 / 角色 / 当前时间取自正文解析（与 Chat 同源），
历史取工作副本（工具落地）。

### 截断（`response.incomplete`）怎么处理

输出触顶时服务商发的是 `response.incomplete`（**没有** `error` 字段，只有
`incomplete_details.reason`）。旧实现把它和 `response.failed` 合并抛异常，
文案恒为「**API 请求中断：null**」，还会连带赔掉本轮已生成的正文。现在：

- 底层（`AiService.responses`）：保留截断前的正文与工具参数，标记
  `AiCallResult.incomplete` + `incompleteReason`，**正常返回不抛异常**；
  `failed` 仍抛，但文案兜底为「服务端未给出原因」，绝不出现 `null`；
- 执行器：给下一帧补一条「减少并拆短工具调用（一个栏目一次调用、edits 尽量
  少、不要复制长段文本）」的指令；截断的响应**不作为续接基点**（下一帧全量重发）；
- **不改请求体的 `max_output_tokens`**：各阶段都按用户设置原样发送，
  触顶属于用户可自行调节的参数，程序只提示不擅改；
- 末帧仍被截断 → 常驻黄框首行给出可操作提示（去设置里调高「最大 token」）；
  正文一帧都没产出时，失败条目的黄框与红框也会写明「被输出上限截断」。

### 一轮的完整流程（`AgentRoundRunner`）

1. **组装**：`instructions`（档位对应的 `PromptMode`）+ 历史消息（Lv.2 每轮
   3 小节 / Lv.1 最新一轮 5 区块 / 更早仅正文）+ 当前用户消息；**不预置任何
   状态**——状态由模型主动调用对应栏目读取器获取。工具集 = 档位对应的状态工具
   （Lv.1 历史一对 / Lv.2 六工具），联网强制开启时叠加搜索 / 打开页工具。
2. **调研阶段（`stage=prepare`，仅 Lv.1）**：契约要求先调
   **一次** `narrchat_readHistory`（历史的唯一来源，本阶段只读一次），需要现实
   资料时联网搜索（`narrchat_webSearch` → `narrchat_webFetchPage`，可多步）。
   **本阶段不产出大纲 / 记忆 / 正文**：文本零输出（写什么都一律丢弃），
   帧上限 `kAgentMaxPrepFrames` = 6。**退出条件**：本帧不再调工具；或本帧工具
   **只有读取器**（读完历史且无联网意图 → 直接进入记忆阶段：无联网时全轮恰好
   3 次请求）。
3. **记忆阶段（`stage=memory`，仅 Lv.1）**：**同一回合**内先在**思考通道**推演
   剧情定下大纲（关键事件 / 出场角色 / 本轮结束时的剧情内时间），再用
   `narrchat_editHistory`（`op=append`）追加**恰好一条**本轮记忆条目（格式
   `- {轮次} | {时间} | {记忆内容}`；{时间} = 大纲里本轮结束时的剧情内时间），
   **记忆先于正文落地，成为正文的既定约束**；文本通道
   关闭，帧上限 `kAgentMaxMemoryFrames` = 3。
4. **正文阶段（`stage=story`，唯一上屏阶段）**：按大纲 +
   书籍设定 / 文笔参考产出正文：
   - Lv.2：`## 剧情演绎` → `## 推荐行动` → `## 当前时间`（时间属于**正文**，
     不设时间工具；应用从正文解析写入工作副本），世界 / 角色 / 记忆区块
     **禁止**出现（违规出现时采纳前剥离）；
   - Lv.1：再补 `## 世界状态` 与 `## 角色状态`（共 5 区块），只有
     `## 记忆总结` 被禁止并剥离（它只以工具结果形式出现）；正文的
     `## 当前时间` 必须与记忆条目时间一致。
   编辑器在正文轮**禁止**：Lv.2 违规仍执行兼容（正确性不依赖它）；Lv.1 的
   `narrchat_editHistory` **不再被拒绝执行**——记忆已在记忆阶段落地，次序本身
   已消解重复条目风险。
   退出条件：本帧无工具调用；或**已采纳标题正文且本帧工具全是编辑器**
   （补齐与否交给维护轮）。含搜索 / 打开页 / 读取器等**喂正文**的工具时继续
   下一帧（结果必须回到上下文）。帧上限 `kAgentMaxStoryFrames` = 8。
5. **缺口判定**（`state_coverage.dart`，纯应用侧事实，不采信模型自述）：
   判定范围 = 档位启用的栏目（Lv.1 只有历史，且关闭角色块懒修改检查），
   见下表（时间不参与判定）。Lv.2 有缺口或正文轮有失败的编辑 → 进入维护轮；
   **Lv.1 仅在记忆未落地 / 校验失败 / 截断等缺口出现时进入维护轮**（合规流程
   零额外请求）。
6. **维护轮（`stage=state`）**：**读取器已禁用**——写正文
   不改变状态（只有编辑会），所以此前读到的那一份快照就是维护轮唯一正确的锚点
   来源，它已在上下文中（护栏见下）。指令（`[State-maintenance turn]`，英文要求
   在前、中文概述在后，不加语言标记）列出待修各项（至多 8 条），要求**在第一个
   响应里逐栏目调用对应编辑器**。
   **优先级：历史（记忆）→ 角色 → 世界**——装不下时先做历史与角色（每轮记忆是
   硬义务）。修复帧同样不读——复用已有结果与失败回传的「栏目当前全文」。
   维护帧「空手帧」（只回文本 / 只试探读取）**不会提前结束**维护轮：
   只要清单还有缺项就继续修复，帧数上限（1 主 + 3 修）兜底。
7. **落库**：工作副本快照合并进本轮 `Round`（Lv.1 的世界 / 角色 / 时间另取正文
   解析结果；每轮仍存全量快照六字段，侧边栏可编辑、云同步与历史结构零改动）。
   **不再有「文本状态兜底」**——工具维护的栏目只能经工具落地，正文里违规出现的
   对应区块**剥离后**才写入正文（Lv.1 的 `## 世界状态` / `## 角色状态` 是合法
   正文段，直接落库）。
8. **警告（两级，同一黄框形态）**：
   - 生成期间：流式气泡顶部实时提示本轮已跳过的项；
   - 结束后：**常驻黄框挂在对应轮次的气泡内**（`RoundProvider.roundWarningsFor`），
     内容 = 维护轮用尽后仍存在的缺口 + 终态仍未修复的栏目，右上角 ✕ 可手动关闭；
     **仅存内存**（不入库、不进云同步、跨设备不体现），重生成该轮 / 修改提问 /
     删除该轮时随轮次一起清除，杀进程即清空；
   - 正文为空的 Agent 轮（模型只返回工具调用）：本轮**不写库**、用户输入走既有
     「失败条目」（可一键重试），并在失败条目下方挂黄框说明「状态改动已作废」。
9. **取消 / 失败**：工作副本整体丢弃，库无半成品（失败条目与 Chat 一致）。

### 「读完再写 → 直接改」：为什么记忆 / 维护帧不再读取

模型的默认习惯是「写完再查一遍再改」（读到一次状态 → 写正文 → 维护轮再读一次
→ 才动手编辑）。这一次重复读取要额外花掉一个帧，且会把此前那份读取结果从
上下文中**顶替**掉（同栏只保留最新一份）。而状态在写正文时**不会变化**——只有
编辑会改变它——所以维护轮的锚点就是此前那一份。Lv.1 同理：**调研阶段读取一次，
记忆帧 / 维护帧直接复用**。为此：

- **提示词**：`prompt_v2_sections.dart` 的三模式契约与记忆 / 维护帧指令都明确
  「读取器在本回合已禁用 / 读取只做一次 / 锚点从对话中已有的结果逐字复制」，
  并要求**第一个维护响应就完成清单**（经 `promptInterface.stage*` 取用）；
- **执行器护栏**（`_refusedRepeatRead`）：**非正文阶段**（记忆帧 / 维护轮）对
  **本轮已提供过全文的栏目**的读取调用**不执行**，回传一行说明（工具框显示 ✕，
  不计入缺项清单）并提示直接调用对应编辑器；被拒绝的读取**不会剔除**此前那一份
  结果（它仍是唯一锚点来源）。已提供过 = 该栏目读取器成功返回过 / 该栏目编辑器
  回传过全文（成功与失败都回传）。调研阶段正在读取的调用不受影响；调研阶段已提供
  过历史全文时，记忆帧再调 `narrchat_readHistory` 会被拒绝。
- **非合规流程不失明**：漏读的栏目、参数被截断的读取，护栏一律放行
  （照常执行）——模型仍能自我修复。

在合规流程下，维护轮因此只需**一个帧**（直接编辑），而不是「一帧读取 + 一帧编辑」。

### 缺口判定

| 缺口 | 触发条件 | 维护轮指令 |
|---|---|---|
| `sectionUntouched` | 栏目既没被编辑、也没 `op=noChange` 声明 | 调用一次**该栏目的编辑器** |
| `sectionUnchanged` | 做过编辑但整栏与上一轮逐字节相同（历史栏除外） | 按最新读取结果做实际编辑 |
| `lazyCharacters` | 本轮正文出现的具名角色，其 `## 角色名` 块与上一轮逐字节相同（**仅 Lv.2**） | 逐行 `op=set` 实际编辑；仅纯提及角色允许 `op=noChange` + `reason` |

当前时间**不参与**缺口判定：它属于正文（`## 当前时间` 小节），
缺失时工作副本沿用上一轮时间（正文质量问题，不作状态缺口）。

## 上下文构成（前缀缓存友好）

各阶段的 `instructions` 与 `tools` **逐字节相同**（后续阶段不裁剪规则、
不换工具集），历史前缀也相同，只有尾部不同 —— 服务商的 prompt cache 在
记忆 / 维护阶段与下一轮都能命中：

- **历史里的 assistant 消息形态随档位**（`AssistantHistoryShape`）：
  Lv.2 每轮只带正文三小节；Lv.1 最新一轮带 5 区块、更早仅正文；Chat 维持原样。
  这是稳定性的关键：历史中一旦出现 `## 记忆总结`（Lv.1）或 `## 世界状态`
  之类区块（Lv.2），模型就会照抄它们。
- **状态**由模型**主动调用**对应栏目读取器获取（**真实注册**的只读工具，
  不预置、app 不伪造条目）：返回值永远是**工作副本当前渲染**
  （Lv.1 调研阶段读取 = 上一轮库内状态，Lv.2 正文阶段读取；记忆 / 维护帧的
  重复读取在合规流程下被护栏拒绝），
  应用侧无需从调用序列区分阶段。结果以 `function_call_output` 形态进入
  上下文——**工具结果，不是输出格式**，不会诱发模型模仿 md 格式把状态
  写进正文；
- **每栏只保留最新一份**读取结果（按工具名剔除旧份，且只有**真正执行成功**的
  读取才剔除旧份——被拒绝的重复读取不得顶掉模型唯一可用的锚点来源），
  输入不随修复帧膨胀；
- **思考块**（`reasoning` 条目）不参与上述剔除：它是服务商「带工具请求必须逐块
  回传」的硬要求（见上文「思考块回传」），每帧按**工具调用数**各发一块、按响应
  顺序累积（剔除过期读取调用时，其紧邻的那一块随笔随删）；
- 读取结果只含**被请求的那一栏**块（`<worldState>` / `<characterState>` /
  `<memorySummary>`，空栏目标 `empty="true"`），与 `Round` 字段一一对应；
  时间不在其中（属于正文 `## 当前时间`）。
- **不约束思考链**：提示词不限定思考的语言与写法（不要求「思考用英文」一类），
  思考链不是输出内容；功能性步骤照旧（调研回合读史、**大纲与记忆条目同回合落定**、
  记忆先于正文、按序三段）。
  思考块本身会随帧回传（服务商要求，见「思考块回传」），因此它同样计入输入
  token 与缓存前缀。
- **修改轮（Chat 页 AI 气泡的「按意见修改」）**：历史 = 被重写轮**生成时收到的
  n 轮 + 该轮自身**（n+1，`RoundProvider.modifyRoundByOpinion`），工作副本的
  `roundIndex` = 被重写轮、基座 = 该轮的**上一轮**——因此三栏读取器读到的世界 /
  角色 / 记忆都停在上一轮，本轮记忆条目仍按被重写轮的轮号落地（`op=append` 校验
  的轮号即被重写轮号）。落库 = 该轮同分组**新增一代**（旧代留在版本树可切回）。

## 协议兼容降级（就地重发同一帧，不烧帧预算）

`_callFrame` 捕获 `AiExceptionKind.api` 的 4xx 类错误，就地降级后重发**同一帧**
（`_frames` 不计数，工具不重复执行；同一帧至多连降 3 项）：

| 症状 | 降级动作 |
|---|---|
| 报错含 `previous_response_id` | 本帧改为全量重发 input |
| 报错含 `reasoning` / `thinking` / `effort` | 维护帧不再覆盖思考强度（回落用户设置；工具参数的输出预算相应少一截，只能靠「拆短调用」指令与用户调高「最大 token」补救） |

只有**内容校验失败**（锚点未命中、记忆缺本轮条目等）才消耗修复帧。

### 思考块回传（带工具的请求必须**逐块**回传 reasoning）

服务商对**携带 `tools` 的请求**有硬性要求，且校验粒度是**逐个工具调用**的
（下表为针对 DeepSeek 官方 `/responses` 线路的**实测**结论）：

| 请求形态 | 结果 |
|---|---|
| 每个 `function_call` 前各一块非空 `reasoning` | **200** |
| 一帧调 N 个工具，只回传 1 块思考 | **400** |
| 某块 `reasoning_text` 为空 | **400** |
| 只回传 assistant 正文、没有 reasoning | **400** |
| 完全不回传 reasoning | **400** |
| 块 id 形态（同 id / 异 id / 无 id） | 均 200（**不校验 id**） |

报错文案：`The reasoning_text in the thinking mode must be passed back to the
API`（Chat 通道为 `content[].thinking`）。这也解释了历史现象：记忆 / 维护轮
一帧通常只调一个工具，一块思考恰好够用；**调研轮 / 正文轮一帧并发调两个工具**
（如 `narrchat_readHistory` + `narrchat_webSearch`）时只发一块 → 必 400。

因此 `AiService` 除聚合文本（`reasoningContent`，界面用）外，还**按条目**捕获
思考块（`reasoningItems`：id / 文本 / 文本形态）；执行器把它挂在 `_frameReasoning`
上，**追加每个 `function_call` 时各发一块**（`_appendCallItems` 按 `callIndex`
取块），无工具调用的帧则在正文前发一块。剔除过期读取结果
（`_pruneStaleReadState`）时**连同紧邻其前的思考块一起剔除**，避免思考掉到会话
开头变成「没有归属的孤儿块」。

两种线路由 `wire_adapters` 还原成各自的回传形态：

| 线路 | 回传形态 |
|---|---|
| Responses | `{type: 'reasoning', id?, content/summary parts}` input item（顺序：每块 reasoning → 其所属的 function_call → function_call_output） |
| Chat | assistant 消息上的 `reasoning_content` 字段（纯工具帧会补一条 `content: null` 的 assistant 承载它与 `tool_calls`） |

联网搜索的工具循环（Agent 关档位）走同一份机制：`AgentRunner` 同样按调用数各发
一块（Responses 线路在展开时还原成 reasoning item；Chat 线路忽略这些条目、改用
同条消息上的 `reasoning_content`）。

两条实现约定：
- **文本形态随响应**：`content` 形态与 `summary` 形态各自按其原形态还原
  （OpenAI 侧 reasoning 的 `content` 是加密形态，纯文本只允许放 `summary`）；
- **不伪造内容**：模型未产出思考时（未开思考 / 服务端没给）不回传凭空编造的
  思考；但**工具调用帧的缺块仍按回落链补齐**（该帧正文 → 占位文本）——服务端
  对缺块是硬 400，宁可回传一段不完美的文本，也不能让整轮生成失败。

#### 回传精简（「精简思考回传」开关）

思考块随每帧全量重发而累积进输入。实测（`deepseek-v4-flash`，约 800 字思考，
同一请求只换块内容）：

| 会话帧数 | 回传真实思考 | 回传最小块 |
|---|---|---|
| 1 | 797 | 641 |
| 2 | 1070 | 758 |
| 3 | 1343 | 875 |
| 4 | 1616 | 992 |

即输入按 **+273 token/帧**（真实思考）vs **+117 token/帧**（最小块）增长。
`ExperimentalSettingsProvider.reduceReasoningReplay`（设置 → 通用设置 →
实验性设置 → **精简思考回传**，**默认关**）开启后按
`lib/services/agent/reasoning_replay.dart` 的规则回传：按**段落**切分、丢弃纯
空白行（`\n\n` 只是格式占位）；**单段原样返回**；**多段取首段 + 末段**。默认关 =
逐字节回传原文（与服务商"完整回传思考"的要求一致）。完全不发 / 只发最后一个
调用的块 / 空文本 / 用正文顶替实测均为 400，可调的只有体积。

### 降级重发的成本（不计帧 / 不计失败轮 / 不计 token）

`supportsThinkingEffort` 是**每轮执行器实例**上的运行时开关：降级结论只在
**本轮**内生效（同一帧后续不再发送该参数），**跨轮不记忆**——下一轮会重新按
用户设置探测一次。这是刻意的：探测失败的成本极低，而记忆会引入「服务商补齐
支持后仍长期不发」的过期状态。

被拒绝的那次探测帧**不是一次失败**，具体地：

- **不计帧**：`_frames` 只在调用真正返回后自增 → 降级重发不算帧数（`AgentRoundResult.frames` 不含它）；
- **不计失败轮**：异常在 `_callFrame` 内被吞掉后就地重发 → 不产生失败条目（`FailedAttempt`）、
  不触发「错误重连……（x/3）」（那是网络类整轮重试的提示）、不产生常驻黄框，本轮照常落库；
- **不计 token**：参数校验类 4xx 在服务端推理前即被拒绝，不返回 `usage`；应用侧本轮用量
  只累加**成功帧**，所以 `tokensIn` / `tokensOut` / `cachedTokensIn` 都不含它；
- **不重跑整轮**：4xx 属 `AiExceptionKind.api`，`_callWithRetry` 只对网络类失败整轮重试
  → 已产出的正文（已花的 token）不会被作废重发。

唯一的成本是**一次额外的 HTTP 往返**（通常几百毫秒），加上 RAW 里多一条记录。

### RAW 里的失败信息

失败的那次交换会记录原因（`RawExchange.error`），RAW 显示
**`请求失败：API 请求失败（HTTP 400）：<服务商报错原文>`**（含 HTTP 状态码）；
既无错误也无返回内容时才显示「（无 AI 返回内容）」。整轮失败时（例如 4xx 无法降级、
网络重试耗尽）该次交换同样带着这条说明出现在「失败轮」的 RAW 里。

## 单轮链式续接（previous_response_id）

默认**关闭**：`previous_response_id` 仅用于“单轮内多次调用”的续接帧，
**永不跨轮**（历史轮次与记忆结构不变，请求体形态跨预算一致）。

- 平台设置 →「允许链式续接（previous_response_id，需服务商支持）」默认关；
- DeepSeek 官方为**无状态 API**（`previous_response_id` / `conversation` /
  `store` 均不支持且静默忽略），关闭时每帧全量重发输入；
- OpenAI 官方等有状态实现可开启：续接帧只发新增输入项（`tools` /
  `instructions` 一并省略）。

## 锚定式编辑（状态栏目）

参考 DeepSeek Harness / Claude 系工具的行级定位机制——**不用行号**（LLM 数行号
不可靠，是「改错行 / 记忆替换第一行」的根源），改为**原文锚点 + 唯一匹配**：

- 六个工具**按栏目成对拆分**（世界 / 角色 / 历史各一读一写），编辑器只改
  自己那一栏：`edits` 只携带**变更的行**；`before` 必须从**本栏目读取器**的
  结果中**逐字复制**（可含 `\n` 连接连续多行）。匹配三级递进：逐字行 →
  归一化行（折叠空白与全/半角标点）→ 归一化行内子串；
  - 未命中 → 报错（提示逐字复制 + 当前行数 + **该栏目当前全文**供重锚，至多 400 行）；
  - 不唯一 → 报错（列出命中行号，引导补充唯一上下文）；
  - 命中 → 只替换该段行，未触及的行字节级保留；
- `op=append` 追加到栏目末尾（历史条目固定用它）；`set` / `insertAfter` /
  `delete` 均以 `before` 锚定；`op=reset` 仅限空栏目 / 首次填入 / 明确重排；
- `op=noChange` **必须携带非空 `reason`**（省略栏目 ≠ 声明无变化），登记进
  `declaredUnchanged` 供缺口判定放行；历史栏**不接受** `noChange`；
  noChange 是**最后手段**：正文里角色/局势只要有新动向（一句反应、一段心理、
  一次移动本就是「变化」），就应写一条 `op=set`；一次调用可带**多条** `edits`
  （每条对应一行改动），提示词与工具描述明确点名「无需大改」这类空泛理由会被
  视为懒修改；
- 同一调用内按顺序应用（锚点在应用时刻解析），**事务化**：任一编辑失败整体不提交；
- 结构性校验：历史（记忆总结）变更后必须恰含一条本轮（轮次 = N）条目
  （解析与计数见 `lib/utils/memory_entry_format.dart`，新格式
  `- {轮次} | {时间} | {记忆内容}` 与旧格式 `- 第N轮｜日期：…｜…` 一并兼容）；
  **合并区间写法**（`- 11~15 | …` / `- 11 - 15 | …`，半角 `-`/`~` 与全角
  `－`/`～` 均可，两端升序归一并保留原分隔符）视为**区间内各轮均已存在**：
  `memoryEntryCount(text, 13)` 对 `11~15` 计 1。档位 > 0 时该校验还要求
  **本轮应做的合并已落地**（见下节）；
- **当前时间不设工具**：属于正文 `## 当前时间` 小节，正文采纳时由应用解析
  写入工作副本（缺失则沿用上一轮时间）；
- 工具结果分两面：`summary`（UI 一行）与 `modelOutput`（回传模型全文，含栏目
  当前全文）；参数被截断（`argumentsUnparsable`）时不执行，回传「一栏目一次
  调用」的重试指引。

### 记忆总结轮次合并（档位驱动，三个模式一致）

每本书的「记忆总结轮次合并」档位（`books.memory_summary_rounds`：0 = 关闭、
5 / 10 = 每个合并项包含的轮次数）决定记忆栏是否把散条目压成区间条目。规则与
落地口径的**单一真源**是 `lib/services/memory_merge_planner.dart`：

- **标准形态**（`kMemoryMergedEntryFormat`）：
  `- 15 - 20 | 仙历十四年五月二十日 ~ 仙历十四年七月八日 | 这期间的事。`
  （轮次区间用 ` - `、时间区间用 ` ~ `）。模型按全局 Markdown 规则把 `~` 转义成
  `\~` 时，解析层用 `unescapeMemoryEntryText` 还原，展示 / 判定都不带反斜杠
  （区间分隔符前置的 `\` 同样容忍）。
- **触发规则**：档位 T > 0 时，**未合并条目**（未被任何区间条目覆盖的单轮条目）
  达到 `2T` 即把**最旧的 T 条**合并为一条区间条目，并重复到剩余未合并条目
  `< 2T`（积压可在同一轮内补齐）。例（T=5，已有区间条目 1-7，散条目 8/9/10）：
  第 11~16 轮都不动作，第 17 轮（未合并 = 10 条）合并 `8-12`。
- **不变量**：已合并条目冻结（不改写 / 不拆分 / 不重排）；本轮新增的那一条永不
  落入区间（区间个数 k 恒满足 `k*T <= count - T`）；尾部未合并片段末条不是上一轮
  （历史缺口 / 乱序）时本轮不动作；档位 0 只注入「不主动合并、已有区间条目原样
  保留」。
- **用户要求优先**：策略文案与 Chat 的本轮指令都写明「若本轮用户输入明确要求
  别的合并方式（或要求不要合并），以用户要求为准」，应用**不做**关键词检测。
- **下发与判定**：计划在**生成之前**一次算定（输入 = 上一轮落库的记忆总结 +
  档位 + 本轮轮号）。Chat 走用户消息（后置词之后，模型改写 `## 记忆总结` 区块）；
  Agent 走记忆阶段帧指令（Lv.1：一个 `op=set` + 多行 `before` 完成一个区间的
  合并，随后照常 `op=append`）或维护轮问题清单（Lv.2）；生成后用
  `isMemoryMergeApplied` 判定（每个区间存在**恰好覆盖它**的合并条目）。
- **未落地的处置**：Agent 的记忆阶段把「合并已落地」并入 `_memorySatisfied()`
  （Lv.2 并入维护轮 pending 清单）继续重试；重试帧数用尽、或 Chat 模式（无回炉
  机会）→ 轮次卡片一条常驻警告（`MemoryMergePlan.uiText`），**不阻断正文**。

## 其它交互

- **正文采纳制（最后一个标题帧胜出）**：本轮正文 = 正文阶段 **最后一个**含
  `## 剧情演绎` / `## 正文` 标题的帧的原始内容；无标题 + 带工具的帧是**开场白**
  （「我先搜索一下…」），不上屏、不采纳、不阻塞真正正文；无标题 + 无工具的帧
  按未按格式输出的正文兜底。门控 `_FrameGate` 在每帧正文首次出现前发
  `AiStreamChunk(narrativeReset)`，界面表现为正文块重置重流（不是拼接）；
- **块顺序**：思考 / 搜索 / 打开页 / 状态工具按 **AI 返回顺序**流式展示；
  正文是「块外」特殊块，插入在其返回位置；
- **统一工具块**：联网搜索 / 打开页面 / 六个状态工具共用同一形态，标题统一为
  `Tool · 工具名`（Chat 模式保留语义化标题）；**一次工具调用只产生一个框**
  （流式预览 / 开始 / 完成共享同一事件，按 callId 匹配）；执行中自动展开明细，
  成功自动收起为一行，失败保持展开完整原因（黄 = 页面拒绝访问，红 = 校验失败）；
- **提示词**：契约规则为**中英双语**（英文规则行在前 + 中文一行摘要，
  字面量与标题名永不翻译），提升模型遵循度；**工具 `description` 统一为
  「英文详细要求 + 简短中文概述」**（两句之间不加【中】一类语言标记）；
- **联网搜索**：Agent 期间强制开启，与状态工具同批注入
  （`narrchat_webSearch` → `narrchat_webFetchPage` → 正文 + 状态工具）；
  **system 不追加任何联网指令**——何时调用、搜索后必须打开页面等要求全部写在
  两个工具的 `description` 里（见 `docs/agent_tools.md`）；
- **视觉**：Agent 模式支持图片输入（responses `input_image` 内容块，仅视觉模型）；
- **非流式**：Agent 期间流式强制开启；模型能力关闭流式时整轮（含维护帧）全非流，
  由 `NonStreamReplayer` 回放，同样经过帧门控；
- **RAW**：RAW 对话框 AI 返回区为「思考块 / 工具调用块 / 正文块」，
  每帧一条交换记录（含维护帧）；**预览请求体 = 实发首帧**（Lv.1 = 准备帧、
  Lv.2 = 正文帧），并在对话框里列出后续**可能**发出的帧（记忆 / 正文 / 维护，
  仅展示相对上一帧的增量字段）——是否发出取决于模型响应。

## 设置页（实验性设置 → Agent 模式）

- **整张卡片任意位置可点**即可展开档位菜单（不必对准右侧箭头）；
  实现用 `MenuAnchor`（与对话页模型选择器同款交互）而非 `DropdownButton`
  ——后者的展开热区只覆盖按钮本身；
- 卡片内只有**简要**介绍：调用自定义工具（`narrchat_*`）走分阶段生成、
  由 Agent 托管部分状态、⚠ 档位开启期间模型已支持的功能（思考 / 流式 / 搜索）
  无法通过对话页指示器关闭、**未来更新可能对本功能做出破坏性变更**、正确性不保证；
- **各档位差异写在下拉选项内**（标题 + 一行说明）：

  | 选项 | 说明 |
  |---|---|
  | 无 | 使用传统 Chat 方式 |
  | Agent Lv.1 | 记忆总结部分将由 Agent 托管 |
  | Agent Lv.2 | 角色状态、世界状态、记忆总结部分将由 Agent 托管 |

- 档位保存到本地配置 `agentModeLevel`（0/1/2）；旧布尔键 `agentModeEnabled`
  只在新键缺失时作为迁移来源（`true` → Lv.2），读取过程不写盘；
- 另有一行 **「精简思考回传」** 开关（Agent 模式专用，**默认关**）：开启后只回传
  思考的首段与末段（单段原样）；默认逐字节回传原文。保存到本地配置
  `agentReasoningReplayReduced`；规则与实测数据见上文「回传精简」。

## 已知限制

- 常驻黄框只在本次进程内有效（刻意不入库：它属于本机生成过程的诊断信息，
  不该进用户数据与云同步），换设备 / 重启后不再显示；
- 懒修改判定按「角色名在正文中原样出现」字面匹配，别名 / 代称不参与；该检查
  **只在 Lv.2** 生效（Lv.1 的角色状态由正文携带，不做逐行字节比对）；
- Lv.1 的历史（记忆总结）无法再依赖「上一轮 assistant 消息」传递，模型必须在
  **调研阶段**主动调用 `narrchat_readHistory`（**只读一次**）；漏读时正文可能
  缺少历史依据（应用侧不兜底）；
- 大纲与正文可能**偏离**：模型在思考通道写的大纲与最终正文未必完全一致；记忆
  条目已按大纲**先行落地**（成为正文约束），偏差由维护轮兜底 / 下一轮提示纠正，
  应用侧不自动回改；
- 记忆条目的时间取**大纲里的本轮结束时间**，正文 `## 当前时间` 应与之一致；
  时间不参与缺口判定，两者不一致属正文质量问题；
- 云同步 / 书籍迁移不感知 Agent 档位（数据形态与 Chat 完全一致，无迁移要求）；
- 旧版本的布尔开关 `agentModeEnabled` 只在**新键 `agentModeLevel` 缺失**时
  作为迁移来源读取（`true` → Lv.2，保持旧行为），读取过程不写盘；
- 记忆 / 维护帧的重复读取护栏按「本轮是否已把该栏目全文交给模型」判断：模型
  完全没读且编辑器从未回传过该栏目的极端情形下，重复读取照常执行（宁可多花一帧，
  也不让模型失去锚点来源）。
