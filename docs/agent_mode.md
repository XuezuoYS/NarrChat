# AGENT 模式（OpenAI Response API 兼容）

本文档说明 NarrChat 的 AGENT 模式：协议选择、生成流程、提示词契约、
锚定式状态工具与已知限制。

## 协议选择（平台）

设置 →「API 设置」中每个平台一个**接入协议**：

- **OpenAI Response API 兼容**（**出厂默认平台「默认（DeepSeek 开放平台）」使用**）：
  自动启用 AGENT 模式；请求 `POST {baseUrl}/responses`；
- **OpenAI Chat API 兼容**：传统 Chat 对话（6 区块输出 + 可选联网搜索循环），
  行为与历史版本一致；
- 「自定义请求体模板」功能已移除（未来以独立于兼容的高级自定义另行设计）。

内置默认平台与自定义平台的「API 类型」下拉均可实时切换
（保存后立即生效，无需重建平台）。

## AGENT 模式如何工作

每轮生成（`AgentRoundRunner` + `AgentStateWorkingCopy`）：

1. **组装**：AGENT 指令（`PromptBuilder` + `PromptMode.agent`，共享段与 Chat 同源）+ 历史消息
   （最后一条 assistant 为代码反序列化的上一轮快照，六区块形态）+ 用户输入
   + 工具集（2 个状态工具恒定注入；联网搜索开启时叠加搜索 / 打开页工具）。
2. **主响应**：同一响应内并行产出 `## 剧情演绎` / `## 推荐行动`（自由文本）
   与状态工具调用（锚定式编辑）；工具只作用于**工作副本**。
3. **校验与落库**：全部通过 → 合并快照原子落库（每轮仍存全量快照六字段，
   侧边栏可编辑、云同步与历史结构零改动）；失败 → 修复轮（错误回传，≤2 次）；
   仍失败 → 应用成功部分 + 钳制跳过 + 流式期间的黄色警告框（不影响正文）。
   另外两项兜底：
   - **完整性检查**：正文已产出但本轮未推进时间 / 未添加记忆条目时（模型
     仅输出正文未用工具），自动发起「补充修复轮」提示补齐；仍不补则钳制警告；
   - **文本状态兜底**：若整轮未使用任何状态工具，但模型在文本中直接写出了
     状态区块（`## 当前时间` / `## 世界状态` 等），按解析文本落库（按区块
     非空回填），避免模型中写出的状态丢失。
4. **取消 / 失败**：工作副本整体丢弃，库无半成品（失败条目与 Chat 一致）。

### 提示词契约（与 Chat 模式的差异）

- AGENT 指令为**全 Agent 流**：仅两个二级标题（剧情演绎 / 推荐行动）；
  世界状态 / 角色状态 / 记忆总结 / 当前时间**不得**在文本中输出，一律走工具；
- 共享段（身份 / 书籍 / 文笔 / 角色层级 / 世界书 / Mod / 前后置词）与 Chat 模式
  同取自 `PromptSections`（单一真源，修改一处两者同步，允许顺序不同）；
- 模式特有的「格式生成要求」收敛于 `AgentPromptFormat` / `ChatPromptFormat`，
  两种模式的共享文案与组装流程统一在 `PromptSections`（按格式规格插入对应槽位）。

### 锚定式编辑维护（状态栏目）

参考 DeepSeek Harness / Claude 系工具的行级定位机制——**不用行号**（LLM 数行号
不可靠，是「改错行 / 记忆替换第一行」的根源），改为**原文锚点 + 唯一匹配**：

- 单选 `narrchat_editSection`：`edits` 只携带**变更的行**；`before` 必须是从
  上一条消息（上一轮快照）中**逐字复制**的行（可含 `\n` 连接连续多行），
  应用侧做唯一匹配校验：
  - 未命中 → 报错（提示逐字复制，含当前行数）；
  - 不唯一 → 报错（列出命中行号，引导补充唯一上下文）；
  - 命中 → 只替换该段行，未触及的行字节级保留——模型**总能准确地修改
    自己想要的那一行**；
- `op=append`：把内容追加到栏目**末尾**（记忆条目固定用它，无需任何定位）；
  `op=set` / `op=insertAfter` / `op=delete` 均以 `before` 锚定；
  `op=noChange` 声明本轮无变化；`op=reset` 仅限空栏目 / 首次填入 / 明确重排；
- 旧版行号参数（`line` / `after` 等）已被移除，模型携带时收到明确报错并
  引导改用 `before` / `append`；
- 每个需要提及的栏目都必须出现在 edits 中（本轮无变化用 `op=noChange`
  声明，不得省略栏目；记忆总结不许 noChange，每轮必须**追加**本轮条目）；
- 唯一的结构性校验：记忆总结变更后必须包含本轮（第 N 轮）条目；
- `narrchat_advanceTime` 仅校验存在（非空），格式由模型自组织；
- 完整性检查按**整轮累计**判定（时间在第 1 帧推进过、后续帧不再调用不误判）；
- 工具调用在流式响应中**即时预览**（与思考块同语义：卡片随 `output_item.added`
  与参数增量出现、随流更新），执行完成后展示执行结果（成功/错误）。

## 单轮链式续接（previous_response_id）

默认**关闭**：`previous_response_id` 仅用于“单轮内多次工具调用”的续接帧，
**永不跨轮**（历史轮次与记忆结构不变，请求体形态跨预算一致）。

- 平台设置 →「允许链式续接（previous_response_id，需服务商支持）」默认关；
- DeepSeek 官方为**无状态 API**（`previous_response_id` / `conversation` /
  `store` 均不支持且静默忽略），关闭时修复帧全量重发输入（频次 ≤2，成本可控）；
- OpenAI 官方等有状态实现可开启：续接帧只发新增输入项。

## 其它交互

- **块顺序**：思考 / 搜索 / 打开页 / 状态工具按 **AI 返回顺序**流式展示；
  正文是「块外」特殊块，插入在其返回位置（此前块在上、之后块在下）——
  不再出现"全部思考堆在正文上方"；
- **统一工具块**：联网搜索 / 打开页面 / 状态工具共用同一工具块形态，标题统一为
  `Tool · 工具名`（Chat 模式保留语义化标题）；**一次工具调用只产生一个框**
  （流式预览 / 开始 / 完成共享同一事件，按 callId 匹配）——不再出现
  「联网搜索框 + Tool 框」双框并存；执行中自动展开状态明细（约 3~4 行，
  页面跳转链逐条流式展示），执行成功自动收起为一行状态栏（结果要点：
  N 条结果 / 重定向 N 次 / 执行结果说明，chevron 展开完整明细），执行失败
  保持展开完整失败原因（黄色 = 页面拒绝访问 HTTP 4xx/5xx，红色 = 校验失败）；
- **AGENT 徽标**：Chat 页左下角模式摘要显示 `AGENT`（协议自动启用，不可手动关）；
- **提示词**：格式约束、契约规则与工具描述均为**中英双语**（提升模型遵循度）；
- **正文采纳制（帧级格式分类）**：本轮正文 = 首个**标题帧**（内容含
  `## 剧情演绎` / `## 正文` 标题）的原始内容；模型在搜索前的说明性开场白
  （如「我先搜索一下…」，无标题 + 带工具调用）**不作为正文**、不阻塞后续
  真正正文，也不上屏；「无标题 + 无工具」帧按**未按格式输出的正文**兜底
  采纳（防止故事因格式不合规丢失）。修复 / 补充帧模型复读的正文（契约
  禁止，但可能发生）被**丢弃**（流式同步不上屏、落库不拼接）——彻底解决
  「两帧各输出一遍正文」与「开场白挤掉真正正文」；修复轮反馈显式声明
  「禁止再次输出正文」，丢弃只影响正文，不影响状态修复与 RAW 追溯
  （RAW 仍保留每帧完整内容；文本状态兜底从全帧内容解析）；
- **联网搜索**：独立开关照旧；AGENT 模式下与状态工具同批注入
  （`narrchat_webSearch` → `narrchat_webFetchPage` → 正文 + 状态工具）；
- **视觉**：AGENT 模式支持图片输入（responses `input_image` 内容块，仅视觉模型）；
- **非流式**：用户选择非流则整轮（主响应 + 修复帧）全非流；
- **RAW**：RAW 对话框 AI 返回区为「思考块 / 工具调用块 / 正文块」——
  工具调用块含全部 `tool_calls`（状态工具、搜索工具均可见），
  每帧一条交换记录（含修复帧）；预览请求体 = 响应式首帧 JSON。

## 已知限制

- 工具事件框在「调用间隙」可见（如工具轮完成 → 正文轮进行中）；单响应完成
  的快速轮次中状态已在落库快照中体现（侧边栏可查看编辑）；
- 状态钳制警告仅在流式期间展示（不落库，不阻塞正文）；
- 云同步 / 书籍迁移不感知 AGENT（数据形态一致，无迁移要求）。
