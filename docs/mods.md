# Mod 设计（`mods`）

> **文档定位**：Mod 的数据形态、七个注入位、每列语义、拼合规则、优先级、导出格式与 3.0 兼容口径。
> **配套文档**：system 模板见 `docs/prompt_v3_system.md`；上下文侧见 `docs/prompt_v3_context.md`；
> 库表、迁移与云同步见 `docs/database.md`。

## 一、Mod 是什么

一份可复用、可分享的提示词包：2 段对话词（前置 / 后置）+ 5 段 system 块 + 1 本世界书。

- 用户 Mod 落 `user_data/narrchat_mods.db` 的 `mods` 表；
- 预置 Mod 由程序内置（引用 `preset::<key>`），不落库；
- 一本书启用多个 Mod 时，按用户排定的顺序依次注入，同列内容之间空一行。

**示例 Mod**：`PresetMods.example`（key 仍是 `world_detail`，展示名「示例 · 世界细节补全」）
把七个通道各用了一遍，内容都是真实可用文案，用来当「字段怎么用」的参照与拼合测试的输入。
它**不在 `PresetMods.all` 里**——不出现在 Mod 管理页 / 书籍 Mod 面板 / 建书流程，
`byKey` 也解析不到它；将来若要正式放出，把它移回 `all` 即可（key 没变，老引用不用改）。
已启用过它的书：`preset::world_detail` 变成失效引用，解析时直接跳过（不报错），
需要效果的话把它的文案复制成一个用户 Mod 再启用。

## 二、七列 → 七个注入位

| 列名（DB） | UI 名称 | 注入到 | 落在哪个模块 | 空值行为 |
|---|---|---|---|---|
| `pre_prompt` | 前置词 | 用户消息前置词区（用户前置词之后） | 上下文侧 | 不接 |
| `post_prompt` | 后置词 | 用户消息后置词区（用户后置词之前） | 上下文侧 | 不接 |
| `system_must` | System 提示词 - 强指令 | `{system_must}` 的段 2~n | must | 不接 |
| `system_prompt` | System 提示词 - 杂项 | `{system_extra}` 的 `# 杂项要求：` 下 | extra | 整个模块消失 |
| `system_setting` | System 提示词 - 设定 | `{system_setting}` 的 `# 书籍设定和要求：` 内、紧随书籍设定 | setting | 不接 |
| `world_book` | 世界书 | `{system_setting}` 的 `# 世界书：` 内、紧随书籍世界书 | setting | 不接 |
| `system_writing_style` | System 提示词 - 文笔要求与参考段落 | `{system_writing_style}` 的 `# 文笔要求与参考段落：` | writing_style | 连标题一起删 |

说明：

- **五个 system 通道统一叫 `System 提示词 - …`**：一眼能看出这几段是往 system 里塞的；
  文笔那一栏用完整的「文笔要求与参考段落」（它注入的块就叫这个名字）。
  这五个名字是**单一来源**（`mod_detail_dialog.dart` 里的 `kModPanel*Title` 常量），
  对话框、Mod 管理列表、书籍设置里的「提供内容」标签都引用它，别在别处另写一份。
- **列名顺序 = UI 顺序**：杂项 → 设定 → 文笔 → 强指令 → 世界书（前置 / 后置词在它们之前）。
  数据库的物理列序是追加的（旧列在前），UI 顺序以代码里的列清单常量与面板枚举为准。
- `system_prompt` 原名「系统提示词」，v3 起语义收窄为「杂项要求」；老 Mod 的内容原样保留，
  只是注入位置从「书籍信息之后」改到 `{system_extra}`。
- `world_book` 保留旧列名（历史原因），它就是世界书通道。

## 三、拼合规则

- **同列多个 Mod**：按书籍设置里的 Mod 顺序依次排开，块与块之间空一行；每块先去掉行尾空白、
  把 3 个以上连续空行折成一个，再 trim（`ModsBundleBuilder.joinBlocks`）——拼合端不信任
  Mod 端传来的文本。
- **世界书**：关键词命中才注入（扫描本轮输入与最近历史轮次），关键词留空 = 恒定生效；与书籍
  世界书共用同一套扫描器。
- **不标身份**：除「杂项要求」的模块标题外，Mod 内容一律不带标题、不出现「Mod」字样——给
  Mod 单独立块，模型就容易把它当成"另一套规则"分而治之，反而压不住通用协议。
- **空块删除**：按 §二 的表执行；`extra` 整模块消失、`writing` 连标题删，其余只是少一段内容。

## 四、优先级

1. system 里的先后：强指令 → 协议 → 杂项 → 书籍数据 → 文笔 → 收口 → 强指令复述。
2. **Mod 只做补充，不压书**：
   - 设定紧随书籍设定、世界书紧随书籍世界书；
   - 文笔块排在「文笔参考范文」之前，范文仍是最高优先级；
   - 唯一例外是强指令——它进 `{system_must}`，并被 `must-` 逆序复现，末尾排在固定段1 之前
     （有意为之：硬指令让人设让位）。
3. **强指令会以两份进入上下文**（正序 + 逆序），token 翻倍：UI 要提示写短。

## 五、导出与导入

- **单 Mod 导出**：`{"type":"narrchat_mod","version":2, …}`，字段为
  `name` / `description` / `prePrompt` / `postPrompt` / `systemMust` / `systemPrompt` /
  `systemSetting` / `systemWritingStyle` / `worldBookEntries`。
- **v1 兼容**：缺三个新字段的按空处理；老的 `systemPrompt` 落到「杂项要求」（最接近它在 v2 的
  实际位置）。
- **旧版本导入 v2**：未知键被忽略 → 三个新块静默丢失。3.1 导入时若发现版本更高，可提示
  「该 Mod 由更新版本导出」。
- **整库导出包**：带 `schemaVersion`，跨版本导入直接报错（已有守卫）。

## 六、与 3.0 的兼容口径

- 3.0 只认 `pre_prompt` / `post_prompt` / `system_prompt` / `world_book`；三个新列在 3.0
  **不显示也不注入**。
- 更麻烦的是**写**：3.0 打开 3.1 的 Mod 库时，sqflite 会静默把库版本写低；此后在 3.0 里保存
  任何一个 Mod，整行替换会把三个新列重置为空——新内容被**静默清空**。
- 对策（三条都要）：
  1. 3.1 侧加「库版本高于当前应用就拒绝打开」的守卫，把静默降级变成明确报错（只保护向后，
     3.0 本身改不了）；
  2. 3.1 打开库时检测「版本是 25、但新列已存在」——说明库存被旧版本降级过，提示一次
     「检测到旧版本访问，新列内容可能已被清空，请检查 Mod」；
  3. UI 在三个新列上标注「该列在 3.0 不生效」。
- **结论**：3.0 与 3.1 的 Mod 库不互通，发布说明里要写清楚。

## 七、UI 约定

- **布局**：宽屏（可用宽度 ≥720）左右分栏——左侧 8 个面板导航、右侧编辑区；
  窄屏是**悬浮窗**（单栏，四周留边距）：标题 + 面板下拉选择器 + 提示 + 撑满的编辑区 +
  底部按钮。**任何宽度都不允许横向滚动**。
- 窄屏不重复面板名：选择器里写的就是当前面板名，下面的编辑区不再来一行标题，
  省下的高度全给多行输入框（输入框自己填满剩余高度、在框内滚动，文字**顶部对齐**）。
- **面板标题下方一行灰字**：`数据库列 system_setting · 注入位置：书籍设定之后（设定块）`
  （最多两行，超出省略）。
- **三个新列**（强指令 / 设定 / 文笔）的面板显示提醒条：`该列在 3.0 不生效`。
- **面板顺序**：基本信息 → 前置词 → 后置词 → System 提示词 - 杂项 → System 提示词 - 设定 →
  System 提示词 - 文笔要求与参考段落 → System 提示词 - 强指令 → 世界书。
- 世界书仍是条目编辑器（关键词 + 内容）；所有多行框沿用 md 高亮与「请尽量避免使用 #/##」提示。
- 查看（只读）与编辑共用同一套布局与面板，只是输入框只读、没有保存按钮。

## 八、验收

| 项 | 断言 |
|---|---|
| 单列映射 | 五列各自只出现在自己的注入位，不串位 |
| 顺序 | 同列多个 Mod 按设定顺序排开，块间一个空行 |
| 空值 | `extra` 空 → 模块消失；`writing` 空 → 连标题删；其余 → 少一段 |
| 世界书 | 关键词扫描与书籍世界书一致（恒定生效条目恒在） |
| 迁移 | v25 → v26 后新列存在、默认空、老数据一字不动 |
| 摘要 | 新列为空时不改变整库摘要（升级不制造冲突） |
| 导出 | v1 ↔ v2 往返；v1 的 `systemPrompt` 落「杂项要求」 |
| UI | 宽窄屏都能切到 8 个面板、无横向滚动；列名 / 注入位置 / 3.0 提示可见 |
| UI（窄屏） | 悬浮窗：四周留边距、下拉选择器当标题、编辑区铺满且文字顶对齐；360 宽下长标题不溢出 |

测试落点：`test/mods_bundle_builder_test.dart`（七段映射与顺序）、`test/mod_test.dart`
（模型与导出往返）、`test/mods_store_test.dart`（新列读写与合并）、`test/mod_detail_dialog_test.dart`
（宽窄屏切换与提示可见）。
