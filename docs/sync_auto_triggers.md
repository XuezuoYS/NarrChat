# 云备份什么时候自动跑

> 一句话：**只在"内容真的变了"的操作节点触发，没有任何定时轮询。**
> 备份的单元与流程见 [`docs/database.md`](database.md) 的「云备份」一节。

## 触发点

| 来源 | 什么时候 |
| --- | --- |
| 启动 | 冷启动首帧后触发一次 |
| 回到前台 | `resumed` 时触发一次（2 分钟内不重复，见下） |
| 书籍 | 新建书、保存书籍设置（世界书 / 启用 Mod 清单一起提交）、删除（清本机；云端只留最新一代并进回收站，墓碑进 library） |
| 轮次 | 生成成功、生成失败（错误代落库）、中断、改正文、改提问、删轮、删除未启用的代、切换版本后写入、按意见修改 |
| 分支 | 建分支、改名、删分支、从此代拷贝链至新的分支 |
| 世界书 | 随「保存书籍设置」一起提交（设置页里的增删改是草稿，不即时落库） |
| Mod | 全局 Mod 的新增 / 修改 / 删除立即触发；某本书的启用清单随「保存书籍设置」一起提交 |
| 图片 | 导入、粘贴、删除（删除走墓碑传播） |
| 设置页 | 保存云同步设置、改「保留份数」 |

书籍设置页里的文本、封面、世界书与启用 Mod 都先留在页面草稿：点顶栏「保存」
才统一落库（刷新 `book_meta.updated_at`），并且**只触发一次**数据面同步。
有未保存草稿时顶栏会提示「存在变更未保存」，关闭 / 返回会先确认。

反过来，**这些不触发**（它们不改内容，只改"选中的是哪一个"）：

- 切版本（`is_using` 变化）
- 切分支（`branch_working` 变化）
- 重载（`reloadCurrent`）

这两条和"刷新 `updated_at`"的规则是同一套：**刷新 `updated_at` ⟺ 触发同步**。

## 门控

`triggerSync()` 先过三道门，任何一道不过就直接返回、**不占用节流窗口**：

1. 已配置 WebDAV（地址 / 账号 / 密码齐全）；
2. 同步模式是「自动」；
3. 自动上传开关打开。

## 回前台的节流

回前台是最容易频繁触发的一个（切出去看个消息再回来）。所以它单独有一层节流：

- 距上次触发不到 **2 分钟** → 跳过，而且**不改写基准时刻**
  （否则连续切来切去会把窗口一直往后推，永远不再触发）；
- 冷启动不节流（那是用户明确打开了应用）。

## 一次同步做什么

1. 先读云端 `sync_config.json` 的「保留份数」（数据面开始前）；
   读不到就**本轮不修剪**，绝不拿内存默认值去删快照；
2. 先处理 `library` / `mods`，再按 `library` 里的墓碑整理已删除的书：
   先清本机残留，再把云端该书单元整理成**只剩最新同步的一代**（更早的代删掉）；
   这一步在发现书单元**之前**，避免把刚删掉的书原地推回去；
3. `BackupPlanner` 逐单元算该做什么（推送 / 拉取 / 跳过 / 冲突）；
4. `BackupRunner` 执行，进度事件映射成「数据面 / 图片面」两条状态给 UI；
5. 冲突**先自动裁决**（见下节），判不了的才问用户；
6. 执行前会关掉相关库连接，落地后各 store 懒重开（Windows 上不关就删不掉旧文件）；
7. 本机没有、云端有的库（换设备后的第一轮）会自动从云端补齐文件。

删除的书不再推数据库；云端只留最新一代，供「云同步 → 已删除 → 书籍回收站」
还原或彻底删除。从未同步过、云端没有快照的书不进回收站。

## 冲突怎么处理（新一代 PK）

### 自动裁决

| 单元 | 比较方式 | 自动结果 |
| --- | --- | --- |
| 书籍 | 三轴 PK：**代数**（`round_stack` 行数）、**最新轮次**（最大轮号）、**更新时间**（`book_meta.updated_at`） | 三轴**全部**指向同一侧才自动采用（本地胜 → 推成新代；云端胜 → 整份替换本地）；有一轴持平、未知或指向相反就交给用户 |
| Mod 库 | **更新时间**（云端清单 `contentUpdatedAt` vs 本地最近一次 Mod 修改时间） | 新者居上；持平 / 未知才问用户 |
| 书架（Library） | 不做二选一，按 `book_uuid` **逐行合并** | 全自动，见下 |

云端一侧的代数、轮次、时间都存在该单元的云端清单里（`latestRoundIndex` /
`roundGenerationCount` / `contentUpdatedAt`）。旧版清单没有代数和轮次字段，
这两轴按「未知」处理，于是那一项会交给用户，不会瞎猜。

### 删除型变更（时间更新，但轮次 / 代变少）

删除轮次、删除某一代的版本，都会让 `round_stack` 行数变少、`updated_at` 变新。
这种「时间更新但轮/代减少」是**破坏性变更**，不能当普通云端更新静默拉下来覆盖本地：

- 云端变少、本地没改：不再直接跟随云端，而是转成冲突 → PK（代数/轮次指向本地、
  时间指向云端 → 不一致）→ 同步中弹三选一 → 冲突决策页让你确认；
- 云端变少、本地也改过：本来就是冲突，决策页的副标题会写清「云端删掉了轮次或代」；
- 云端变多 / 只是改文字：仍按普通云端更新自动拉取（不打扰）。

判断只看云端清单里的代数：旧版清单没有该字段（0）时无法判断，维持原来的跟随
逻辑，不凭猜测拦同步。

### 书架自动合并

书架是「身份证 + 墓碑」的集合，整份替换会丢本地离线新增的书、或把别处刚删掉
的书原地复活。所以按行合并：

- 只有一侧有 → 原样保留（本地新增不丢、云端新增补进来、墓碑继续传播）；
- 两侧都活 → 留活，书名副本优先用本地（书名信源在 `book_meta`，会自愈）；
- 两侧都是墓碑 → 取 `deleted_at` 更新的那条；
- 一侧活一侧墓碑 → 比「墓碑的删除时间」与「活侧书库的内容时间」：活侧更新就留活
  （回收站还原不会被旧墓碑反杀），墓碑更新就留墓碑；活侧时间读不出来时**墓碑胜**
  （删除是显式动作，绝不静默复活）。

合并后把书架基线改成云端那一代，并在本轮结束后补跑一轮，把合并结果推成新代。
两侧书架的 `master_uuid` 不一致（不是同一套数据）时不硬合，降级成人工二选一。

### 需要用户介入时

1. 同步跑到第一个判不了的冲突时，弹三选一对话框：
   **冲突决策（逐项选择）** / **采用云端备份** / **暂停同步并改为手动**；
   后两个都带二次确认，取消确认就转入冲突决策。
2. 选「冲突决策」：本轮继续把其它单元跑完（不再打扰），结束后**自动打开
   「同步冲突决策」页**。
3. 决策页逐项展示：书名 / Mod 库 / 书架、PK 三轴本地 vs 云端、云端第 N 代与
   写入设备时间、两侧预览（书籍设置 / 世界书 / 启用 Mod / 最近一轮正文，
   Mod 库逐条 diff，书架活书与墓碑 diff）。整本二选一，可批量选择，确认后应用。
4. 页面关掉但没选也没关系：冲突会保留，云同步面板顶部与首页同步状态章都有入口；
   **之后每次同步跑完都会再次自动打开决策页**（页面还开着时不会叠第二层），
   直到冲突被处理掉——不会出现「拒绝同步、又不上传本地」的静默僵局。

「采用云端」只作用于当时还待定的项；书架仍然走自动合并，避免多丢本地书架行。


## 什么算"内容变了"

摘要只按 **DB 文件内容**算，并且排除这些列：

- 所有时间戳（`created_at` / `updated_at` / `operated_at` / `last_round_at`）；
- `branches.branch_working`（当前分支是视图状态）；
- `book_meta` 的身份列（`book_uuid` / `master_uuid` / `database_version`）。

不排除的话，"只是打开看了一下"也会被当成变更，云上会一直出新代。

墓碑只取「是否删除」这个布尔（`deleted_at` 的具体时间不进摘要），删除时轮号
`deleted_round_index` 同样不进摘要（它只是回收站展示信息）。所以删书会让
library 产生新代、把删除传播出去，但反复重写同一个墓碑不会制造新代。

摘要 SQL 里的**列名一律加引号**：SQLite 会把裸写的 `current_time` 当成
`CURRENT_TIME` 关键字（查询那一刻的墙上时间），摘要每秒都变，于是"没改也每次
+1 代"（v3.0 修过的 bug）。`order` / `key` / `group` 这类保留字同理。

## 失败与重试

- 单文件读写失败重试 3 次（30ms / 120ms 退避）；
- 单本已删书的云端整理失败只记该书的错误，下一次同步重试，不影响其它单元；
- 整轮同步失败不改本地数据，状态与原因显示在云同步面板；
- 用户取消立即停（取消不看平面，是全局的 —— 已知取舍，后续可能改成按平面）。

## 有意不做的三件事

1. **不迁移旧云端快照**，也不弹"检测到旧数据"的提示 —— 旧格式直接忽略；
2. **不做逐部件合并**（那是 R2 的做法），冲突只给整本书一个选择；
3. **不做定时轮询**，空闲时没有任何后台请求。
