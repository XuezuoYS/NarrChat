# 云备份什么时候自动跑

> 一句话：**只在"内容真的变了"的操作节点触发，没有任何定时轮询。**
> 备份的单元与流程见 [`docs/database.md`](database.md) 的「云备份」一节。

## 触发点

| 来源 | 什么时候 |
| --- | --- |
| 启动 | 冷启动首帧后触发一次 |
| 回到前台 | `resumed` 时触发一次（2 分钟内不重复，见下） |
| 书籍 | 新建书、改设置 |
| 轮次 | 生成成功、生成失败（错误代落库）、中断、改正文、改提问、删轮、切换版本后写入、按意见修改 |
| 分支 | 建分支、改名、删分支 |
| 世界书 | 新增 / 修改 / 删除条目 |
| Mod | 新增 / 修改 / 删除、某本书的启用清单变化 |
| 图片 | 导入、粘贴、删除（删除走墓碑传播） |
| 设置页 | 保存云同步设置、改「保留份数」 |

反过来，**这些不触发**（它们不改内容，只改"选中的是哪一个"）：

- 切版本（`is_using` 变化）
- 切分支（`branch_working` 变化）
- 重载（`reloadCurrent`）

这两条和"刷新 `updated_at`"的规则是同一套：**刷新 `updated_at` ⟺ 触发同步**。

## 门控

`triggerSync()` 先过三道门，任何一道不过就直接返回、**不占用节流窗口**：

1. 已配置 WebDAV（地址 / 账号 / 密码齐全）；
2. 同步模式是「自动」；
3. 自动上传开关打开。

## 回前台的节流

回前台是最容易频繁触发的一个（切出去看个消息再回来）。所以它单独有一层节流：

- 距上次触发不到 **2 分钟** → 跳过，而且**不改写基准时刻**
  （否则连续切来切去会把窗口一直往后推，永远不再触发）；
- 冷启动不节流（那是用户明确打开了应用）。

## 一次同步做什么

1. `BackupPlanner` 逐单元算该做什么（推送 / 拉取 / 跳过 / 冲突）；
2. `BackupRunner` 执行，进度事件映射成「数据面 / 图片面」两条状态给 UI；
3. 冲突不自动裁决，攒到 `unresolvedConflicts` 等用户选（整本书二选一）；
4. 执行前会关掉相关库连接，落地后各 store 懒重开（Windows 上不关就删不掉旧文件）。

## 什么算"内容变了"

摘要只按 **DB 文件内容**算，并且排除这些列：

- 所有时间戳（`created_at` / `updated_at` / `operated_at` / `last_round_at`）；
- `book_meta.branch_working`（当前分支是视图状态）；
- `book_meta` 的身份列（`book_uuid` / `master_uuid` / `database_version`）。

不排除的话，"只是打开看了一下"也会被当成变更，云上会一直出新代。

## 失败与重试

- 单文件读写失败重试 3 次（30ms / 120ms 退避）；
- 整轮同步失败不改本地数据，状态与原因显示在云同步面板；
- 用户取消立即停（取消不看平面，是全局的 —— 已知取舍，后续可能改成按平面）。

## 有意不做的三件事

1. **不迁移旧云端快照**，也不弹"检测到旧数据"的提示 —— 旧格式直接忽略；
2. **不做逐部件合并**（那是 R2 的做法），冲突只给整本书一个选择；
3. **不做定时轮询**，空闲时没有任何后台请求。
