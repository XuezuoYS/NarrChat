# 云同步：两平面架构、触发时机与并发策略

> 代码入口：统一触发 `CloudSyncProvider.triggerSync({kind, silent})`；
> 手动「同步」按钮 `CloudSyncProvider.sync()`。
> 协调层：`lib/services/sync/sync_coordinator.dart`（`SyncCoordinator`）；
> 数据平面执行器：`database_sync_runner.dart`（`DatabaseSyncRunner`）；
> 图片平面执行器：`image_sync_runner.dart`（`ImageSyncRunner`）。

> **身份层**：书籍 / Mod 以 **UUID v4** 为跨设备同步身份（`books.uuid` / `mods.uuid`，
> 本地生成、服务器不参与分配）；title / name 仅为展示与「首连 / 旧版格式」回退匹配。
> 同步共基表 `sync_book_base` / `sync_mod_base` 以 uuid 为主键；
> manifest `format=2`（旧格式缺 uuid 时按名称回退，兼容读取）。

## 0. 两平面：两条独立生命周期 + 一个统一直排触发

云同步拆成两个**平面（plane）**，各自规划、各自落地、各自 UI 指示；
仅通过统一接口 `triggerSync(kind)` 触发：

| | 数据平面（data） | 图片平面（images） |
|---|---|---|
| 迭代 | manifest 代数（**唯一**代数通道） | 无代数；墓碑条目（1 年 TTL）+ 内容寻址 blob 收敛 |
| 文件 | `manifest.json` / `narrchat_snapshot_gN_*.db` / 本地共基、状态 | `img/*` blob + `img_tombstones.json`（云端与本地工作副本） |
| 规划 | 三向部件合并（`SyncMergePlanner` + `SyncActionPlanner`） | 本地盘 ⊕ 云端 blob ⊕ 墓碑（`ImageSyncPlanner` + `mergeTombstones`） |
| 复活 | —（数据以 uuid 身份三向合并） | **全局复活标记**（`revived: path → 时刻`，随墓碑文件传播）：合并时抵消所有设备上 `deletedAt <= revivedAt` 的陈旧条目；晚于标记的新删除不受影响 |
| 失败模式 | 快照 / 清单写失败 → 本轮中止 | 单张 blob 失败 → 下次重试，不挡数据同步，反之亦然 |
| 触发 | 书 / 轮次 / Mod / 世界书变更（数据类节点） | 图片库删除；数据类触发自动附带图片补跑 |
| UI | HUD「数据同步」段 + 面板「数据」徽章 | HUD「图片同步」段 + 面板「图片」徽章 |

设计收益：

- **代数准确性从"约定"变成"结构保证"**：图片平面没有 manifest 写通道，
  无论图片逻辑怎么改都不可能误推 `manifest.generation`；
- **独立重试 / 独立进度**：几十张大图慢慢传，不会让"数据同步"一直显示同步中；
  图片失败重试也不会反复白写快照；
- 图片平面**不读数据库**：本地 `img/` 盘是云端镜像（含未入正文的导入图）；
  DB 引用集仅作为 manifest.images 展示项由数据平面维护。

### 数据平面合并语义（部件级三向；轮次只认"单纯增"）

书籍按 4 个部件做三方（共基 base / 本地 / 云端）判定：**书籍设置**、**轮次**、
**世界书**、**书-Mod**；独立 Mod 单部件。全部是**整串指纹三向**（不变 / 仅本地
改 / 仅云端改 / 双改），轮次部件在「双改」时多一步极简复核（见下表）。

| 情形 | 结果 |
| --- | --- |
| 部件双端都改且内容不同 | 真冲突 → 冲突对话框 + 合并决策页 |
| 部件双端改出**相同**内容 | `unchanged`（假冲突消除，不弹窗） |
| 轮次：**单纯增**——一侧与共基一致、另一侧在其尾部追加 m 轮（前 n 轮逐行一致） | 自动：本地 n 轮、云端 n+m 轮 → 拉取 m 轮；反之 → 推送（"n 轮一致"= 完整行文本逐行相等） |
| 轮次：双方各自新增（哪怕都是纯新增、位置错开） | **冲突 → 弹页用户决策，不做自动并集** |
| 轮次：同一轮双端改出不同内容、删除 vs 修改、删除 vs 对端新增 | 冲突 → 弹页 |
| 轮次：双端轮次内容**逐行完全一致**、仅失败条目草稿不同（用户不可见） | 视为单纯增（m=0）：推本地、对端下次拉取，**不弹页** |
| 设置类部件（书籍设置 / 世界书 / 书-Mod）或已有 Mod 内容**仅云端改过**（remoteOnly） | **不再静默应用**：折叠进同一条确认通道 → 冲突对话框 → 合并决策页逐本选择「导入 / 保留本地」；未处理前每次同步都会再次提醒（「取消同步」仍会切手动模式止弹） |
| 全新书籍 / 全新 Mod 导入、单侧删除传播、轮次单侧拉取 | 保持自动（"增量"不打扰） |

要点：

- **行比对 = 完整呈现文本**（指纹 `SyncFingerprint.round` 的 13 字段行串：输入、
  正文、世界状态、角色状态、摘要、时间、tokens、模型、图片……），逐行字符串
  相等即"一致"；不做哈希、**零数据库结构变更**。
- **单纯增以共基锚定**：只有"一侧的行序列恰好等于共基、另一侧等于共基行序列 +
  尾部新增"才自动；防止「对端删了轮 + 本端仅失败草稿变化」被误判成新增而把
  已删轮次推回复活（该形态 → 冲突弹页）。
- **失败条目（`failed_*`）不做特殊处理**：它是轮次部件聚合串里的不透明分量，
  单侧改 → 照常推/拉；双端各改 → 轮次行一致时按纯增量推本地（对端随后拉到
  同一草稿），行不一致时本来就落进冲突判定。
- 「保留本地 + 推送」是对云端版本的**显式覆盖**：对端下次同步会因同样的确认
  弹窗再次看到该变更；两端各自坚持「保留本地」时会互相覆盖最后一次确认的结果
  （人工裁决，不做自动仲裁）。

**「并行」≠ 并发**：两平面共享同一 WebDAV 目录与软锁 `sync.lock`，
同设备上的读-改-写互斥由协调层**单执行道串行派发**保证；
跨设备并行本来就由软锁保证。双平面同时待跑时**数据优先**
（数据落地会改变图片引用集，图片随后收敛）。

## 1. 自动同步触发节点（白名单）

**只有用户真实操作才会发起备份/同步**：全自动模式（`syncMode == auto` 且已配置
WebDAV）下，仅下列节点会请求同步（kind 见括号）：

| 节点 | 触发位置 | kind | 说明 |
| --- | --- | --- | --- |
| 打开软件 | `main.dart` 首帧回调 | both | 启动即拉取远端变更、推送本地未同步内容 |
| 回到前台 | `CloudSyncProvider.didChangeAppLifecycleState`（resumed） | both | 静默同步（成功不提示）；视作"再次打开 APP"，受 2 分钟节流（见下） |
| 点击进入书籍 | `ChatScreen.initState` 首帧回调 | both | 进入对话页时拉取最新远端变更 |
| 打开书籍设置 | `BookSettingsScreen.initState` 首帧回调 | both | 静默同步：编辑前先拉取最新书籍设置 |
| 生成结束（成功 / 失败 / 中断） | `RoundProvider.sendRound` finally | both | 轮次落库后触发；轮次可能带图，图片补跑一起排 |
| 书籍设置修改保存 | `BookProvider.createBook` / `updateBook` | both | 书籍设置、世界书、Mod 配置保存后 |
| 世界书条目增/改/删 | `WorldBookProvider.addEntry` / `updateEntry` / `removeEntry` | both | 世界书属书籍设置部件，修改即触发 |
| Mod 修改保存 | `ModProvider.addMod` / `updateMod` / `deleteMod` / `saveBookModConfigs` | both | Mod 新增 / 编辑 / 删除 / 书籍挂载保存后 |
| 图片库删除 | `ImageGalleryPage` 删除确认完成 | **images** | 纯删除意图传播，不产生任何数据平面工作 |

要点：

- **白名单即闭集**：除上表节点外，任何地方都不得引入定时 / 空闲触发
  （`attachLifecycle` 只注册生命周期观察者，**已彻底移除每分钟 `Timer.periodic`
  静默轮询**——空闲停在首页时不再周期性打网络）。新增触发点前先确认它对应
  一次真实的用户操作。
- **回前台节流**：`resumeSyncThrottle = 2 分钟`。每次 `triggerSync()`（含手动
  `sync()`）都会记录 `lastSyncRequestAt`；resumed 时距该时刻不足 2 分钟直接跳过
  （被跳过的触发不改写基准）。Android 切后台返回、Windows 从最小化恢复、
  文件选择 / 权限弹窗返回都会命中 resumed，无节流即等同空闲反复同步。
- 所有节点复用一个入口 `triggerSync()`（`SyncKind.both / data / images`），
  **策略判断集中在 CloudSyncProvider 一处**（是否已配置、是否全自动、回前台节流），
  各业务模块只负责「什么数据变了」这件事，不重复判断。
- 手动模式（`manual`）下所有自动节点都静默忽略（含仅图片触发），
  只有「同步」按钮会真正执行（两平面同时派发）。
- 移除轮询后的兜底责任转移：图片平面的失败重试 / 未入正文的导入图收敛，
  由**下一个操作节点**（进书 / 新轮次 / 图片库删除 / 手动「同步」）承担。

## 2. 并发策略：统一队列 + 分平面排队

```
triggerSync(plane A)  ──► 执行道空闲？ ── 是 ──► 立即派发（syncing）
                              │ 否
                              ▼
                      平面 A 待跑位 = true（多次触发合并为一个）
                              │
当前任务结束（协调层 _pump）──► 有待跑？ ──► 数据优先补跑 ──► 循环
                              │ 无
                              ▼
                        执行道空闲（onIdle 完成）
```

- 任何时刻最多只有 1 个同步在跑（不分平面）：两平面都涉及对同一云端目录的
  读-改-写，并发执行会互相覆盖（manifest 竞态、墓碑竞态、重复上传）。
- 多个触发点快速连发会**按平面各自合并成一次**补跑，不会出现同步风暴；
  合并时静默标记取**与运算**（任一非静默触发 → 结果需要提示，手动点击不静）。
- 两平面幂等（pull → merge → push / 盘⊕云⊕墓碑收敛，无变更时不做任何写入），
  补跑永远安全；结论：**不需要「取消重同步」**（取消反而引入中间态复杂度）。

### 取消按钮与队列的交互

HUD 胶囊每段有**独立的取消按钮**（`cancelSync(plane)`）：

- 置该平面 `cancelRequested`（Runner 在阶段间 / 逐文件检查，协作式停止，
  不写入云端；图片平面不回写墓碑，本地工作副本保留离线改动下次重放）；
- 同时清空**该平面**的待跑位（否则取消后立刻被排队补跑，等于没取消）；
- **另一平面不受影响**：取消图片慢传不中断数据推送，反之亦然。

## 3. 推荐文档化的后续增强（当前已知限制）

本次修复没有做、但建议后续迭代的几个点：

1. **防抖（debounce）**：目前是「执行期间合并」，如果用户连续快速操作（连续发多轮
   消息），每轮结束都会触发一次完整同步。可以再加 1~3 秒防抖窗口（最后一次触发后
   1s 才真正执行），进一步减少网络请求；代价是同步时机略有延迟。
2. **定时重试**：失败后（如网络抖动）可对自动同步加指数退避重试（建议最多 2 次、
   间隔 1min/5min）。当前失败只提示一次、依赖下一个操作节点重试
   （两平面互不阻塞：图片失败随下一个 both / images 触发重试）。
   注意：这与已移除的"每分钟静默轮询"不同——退避重试必须有明确的失败上下文与
   次数上限，不能变成常态化空闲打网络。
3. **首次连接分支的语义**：首连弹窗的三个选项（合并 / 云端覆盖本地 / 本地覆盖云端）
   已接入数据平面任务流；「合并」默认进入逐本合并决策页（等同冲突处理入口）。
   图片平面不依赖首连结果（无 manifest 也能独立收敛 blob 与墓碑）。
4. **图片导入即时上云**：当前图片仅在既有触发节点（轮次落库 / 图片库删除 / 手动）随
   both 触发上传；如需"导入即传"，在导入成功处调用
   `triggerSync(kind: SyncKind.images)` 即可（协调层天然支持）。

## 4. 同步结果提示

两平面各自通过**应用级悬浮气泡**（`SyncResultBubble`，挂在主界面顶层 Stack，
与同步 HUD 同层、展示于标题栏下方；数据源 `CloudSyncProvider.showSyncResult`）
展示结果，文案带平面名以免混淆：

- 数据平面（代数已知时前缀「云端记录 #N：」，内文已精简去重）：
  `云端记录 #N：数据已同步` / `云端记录 #N：已拉取最新数据` /
  `云端记录 #N：已是最新`；首连导入 `云端记录 #N：已导入云端数据`（无快照可导入时
  无前缀）。成功类悬浮 **2 秒**后自动消失；
- 图片平面（无代数通道，格式 `图片同步：{结果}`）：有实际收敛时
  `图片同步：完成（上传 N · 下载 M · 删除 K）`；无变更静默（仅墓碑维护不打扰）；
- 失败：代数已知 → `云端记录 #N：数据同步失败：…`（中途失败携带本轮读到的
  代数；锁/清单未读到则不加前缀）；图片平面 `图片同步：…`。均显示完整错误原因，
  **驻留**等待用户点击「关闭」，内容为可选中文本（可长按复制报错详情）；
- `已取消数据同步` / `已取消图片同步`（HUD 分平面取消 / 首次连接取消）各有明确文案
  （无代数，不加前缀），悬浮 2 秒后自动消失；
- 多条结果（数据 / 图片先后结束）纵向堆叠（最多 3 条，同文案去重），
  同步进行中（HUD 可见）时气泡自动下移一排避让；
- 进入合并决策页（解决冲突）时不弹结果提示，合并落定后的补同步会给出结果。

## 5. 触发链路速查

```
冷启动首帧 / 进入书籍 / 打开书籍设置 ──────────────────────────► triggerSync()（both / 静默）
业务写入（DAO 落库）      ──►  Book/Mod/Round/WorldBook Provider ──► triggerSync()（both）
图片库删除               ──►  ImageGalleryPage ─────────────────► triggerSync(kind: images)
回前台 resumed           ──►  距 lastSyncRequestAt ≥ 2 分钟？────► triggerSync(silent)（否则跳过）
                                                                      │
              未配置 或 manual ──► 忽略（返回）                          │
              SyncCoordinator：同平面合并排队；执行道串行；数据优先       │
                                  空闲 ──► 派发对应平面任务 ────────────┘
       数据任务：锁定 →（首连分支）→ merge → pull 落地 → push（推代数）
                                        │
                          真冲突 / 云端单侧设置、Mod 变更待确认 ──► 冲突对话框
                                         ├─ 取消同步 → 中止 + 手动模式
                                         └─ 解决冲突 → 合并决策页 → 合并落定
                                                        └─ rebase + 补同步推送
       图片任务：锁定 → 墓碑合并 → pull / 删除传播 / upload → 墓碑回写（无代数）
```
