# 第三版上下文管理（v3 context）

> **文档定位**：v3 **上下文侧**的评审真源——本轮 user 消息、历史 messages、Agent 回合指令
> 怎么拼、按什么顺序进请求。
> **配套文档**：system 侧见 `docs/prompt_v3_system.md`；取用接口见 `docs/prompt_v3_interface.md`。
> **适用版本**：v3.1.0（v2 已归档到 `docs/old/ai_prompt_v2.md`）。

## 一、上下文分几层

| 层 | 落在请求的哪儿 | 谁产出 | 每轮变不变 |
|---|---|---|---|
| system | 一条 system 消息 | `prompt_v3_build`（见 system 文档） | 稳定；工具开关一变才变 |
| 历史 | `messages` 里的 user / assistant 交替 | `wire_messages.buildHistoryMessages` | 只追加，不回改 |
| 本轮 user | `messages` 最后一条 user | `prompt_v3_context` | 每轮全新 |
| Agent 回合指令 | 一轮内追加的 user 消息 | `prompt_v3_context` | 每回合一份 |
| 工具结果 | `function_call_output` | 各工具执行器 | 回合内 |

一句话分工：**system 说"你是谁、按什么规矩"，上下文说"这一轮让你干什么、前面发生过什么"。**
两层各管一段，改动互不越界——改 system 不碰 user 模板，改上下文不碰模块顺序。

## 二、本轮 user 消息的成分

设计上拆成 8 个**成分**（顺序固定），发请求时按这个顺序合成**一条** user 消息：

| # | 成分 | 内容 | 空则 |
|---|---|---|---|
| 1 | 头部 | 「创作第 {轮次} 轮」/「重写第 {轮次} 轮」 | 恒在 |
| 2 | 时间行 | `- 上轮时间：…` / `- 此轮时间：…` | 整行删（连它前面的空行） |
| 3 | 前置词 | 用户前置词 → Mod 前置词 | 整区删 |
| 4 | 主人输入 | `【主人的输入】` … `【主人的输入stop】` 包裹 | 恒在 |
| 5 | 后置词 | Mod 后置词 → 用户后置词 | 整区删 |
| 6 | 记忆合并 | Chat 的本轮合并指令 | 无合并动作则整段删 |
| 7 | 文风口径 | 优先顺序那句 | 恒在 |
| 8 | 总协议2 | 模式 user 契约 | 恒在 |

区段之间用 `---` 分隔，成分之间空一行。模板里的 `{}` 都是占位符，取值来源见下面各节；
前后置词是**整段注入**，不拆成词。

### 新建轮

```markdown
你需要按照主人的要求，创作第 {轮次} 轮：

- 上轮时间：{上轮时间}（`## 当前时间` 必须沿用此格式，仅按剧情推进更新时间内容，不得随意改变格式）

---

{用户设置的前置词}

{mod前置词}

---

【主人的输入】

{用户本轮输入}

【主人的输入stop】

---

{mod后置词}

{用户设置的后置词}

---

写文本前先记住文风口径的优先顺序：**本轮主人的要求 > 文笔参考范文 > 文笔要求 > 其他**；历史里 assistant 的文笔文风不作依据，符合格式且剧情与状态保持连贯即可。

# 总协议2

{协议需求user注入于此}
```

- 首轮没有上轮时间、或该轮没有时间可取 → 时间行整条不注入；
- 前置词区 = 用户前置词在前、Mod 前置词在后（Mod 更贴近输入）；
- 后置词区 = Mod 后置词在前、用户后置词在后（同样让 Mod 更贴近输入）；
- `# 总协议2` 下按模式取 user 契约（见下）。

### 修改轮

与新建轮**逐字同构**，只有头部两处不同：

```markdown
你并没有按照主人的要求完成，你需要按照主人的要求，重写第 {轮次} 轮：

- 此轮时间：{此轮时间}（`## 当前时间` 必须沿用此格式，仅按剧情推进更新时间内容，不得随意改变格式）
```

`{轮次}` = 被重写的轮号；`lastRound` 语义 = 被重写轮的**上一轮**（生成基座），所以记忆合并、
前置 / 后置词照旧；`{用户本轮输入}` 位置放用户填的修改意见。历史侧给的是"被重写轮生成时收到
的 n 轮 + 该轮自身"。

### `# 总协议2` 的正文

Chat：

```markdown
现在开始动笔：直接输出 6 个二级标题区块（`## 剧情演绎` → `## 推荐行动` → `## 当前时间` → `## 世界状态` → `## 角色状态` → `## 记忆总结`），从 `## 剧情演绎` 开始；`## 记忆总结` 按「记忆条目格式」要求逐轮逐条目复述、不许缺轮。不要复述指令、不要解释、不要加区块以外的内容。
```

Agent Lv.1：

```markdown
现在开始，按两步来：第一步先调用 `narrchat_readHistory` 一次（需要现实资料就联网）。调研结束后立刻在思考通道定大纲并写正文，只输出 5 个二级标题：`## 剧情演绎` → `## 推荐行动` → `## 当前时间` → `## 世界状态` → `## 角色状态`；`## 当前时间` 写本轮结束时的时间，格式沿用历史。第一步禁止输出 `## 记忆总结`，禁止调用历史编辑器。第二步会由应用单独发起：只根据正文的 `## 当前时间` 用 `narrchat_editHistory` 追加本轮记忆条目，不改正文、世界、角色或时间。禁止复述历史与工具结果，禁止复述本指令。
```

### Chat 的本轮记忆合并指令

位置：后置词之后、文风口径之前；没有合并动作就整段不注入。Agent 不走这里——合并指令跟着维护回合走（见 §四）。

```markdown
【本轮记忆合并】本轮必须完成以下合并，其余条目一字不改：
  - 第 {开头轮}~{结尾轮} 轮（{条数} 条）合并为一行：`- {开头轮} - {结尾轮} | {开头轮时间} ~ {结尾轮时间} | {记忆内容}`
`{记忆内容}` 写成能记住这期间关键事件与因果的内容（长度不限）。被合并的那几行整行替换为上面这一行，`## 记忆总结` 的其它行逐字保留、顺序不变。若本轮【主人的输入】明确要求别的合并方式（或要求不要合并），以主人要求为准，不做上面的默认合并。
```

## 三、历史 messages 的形态

- 每轮 = 一条 `user`（**原样 userInput，不套任何注入外壳**）+ 一条 `assistant`；
  插在 system 之后、本轮 user 之前；
- assistant 侧形态是模型的**模仿对象**，必须与该模式的输出契约一致：

| 模式 | 最新一轮的 assistant | 更早的轮次 |
|---|---|---|
| Chat | 完整 6 区块（原生反解析） | 只给 `## 剧情演绎` 正文 |
| Agent Lv.1 | 5 区块（去掉 `## 记忆总结`） | 只给正文 |

- **取哪几轮**：最近 N 轮父轮次，N = 书籍设置里的「历史条数」（至少 1 轮）；
- **整轮全空**：留一条「（无正文）」占位，别发空 assistant 消息；
- **历史是档案不是范本**：剧情、格式、状态照旧跟，文风别学它（口径见 system 文档 §九）；
- **图片**：该轮用户有图时，那条 user 的 content 从字符串变成
  「文本 + `image_url` 数组」（vision 格式），其余不变；
- `agentStoryOnly`（Lv.2 每轮只给正文三小节）的形态与实现作为框架留在 `wire_messages.dart`，
  当前没有档位使用。

## 四、Agent 回合指令

各回合的 system 与工具集**逐字相同**，只有尾巴不同；回合指令作为一条 `user` 消息追加，
不是 system、也不是用户输入。

| 回合 | 这一回合要做什么 | 文本通道 |
|---|---|---|
| 调研 | 先读一次记忆 + 需要时联网（多步）；不产出记忆 / 正文 | 不上屏、不采纳（零输出口径） |
| 正文 | 调研结束后立刻写 5 区块正文；不写记忆、不调用历史编辑器 | **唯一正文上屏回合** |
| 维护 | 正文完成后单独请求：只补本轮记忆条目 / 合并 | 只进维护流式框 |
| 修复 | 接在维护之后：只按清单补缺口 | 只进维护流式框 |

`{调研回合指令}`：

```markdown
【调研回合】本回合只做调研：先调用 `narrchat_readHistory` **一次**（以往轮次的记忆只有这一个来源），需要现实资料就联网搜索 / 打开页面（可以多步）——确定要联网，就**在本回合一起发起**。**不要在文本通道输出任何内容**：进度汇报、「准备完成」之类都不要写，本回合的文本不会被采纳。读完历史、调研够了就停止调用工具；应用会立刻发正文回合，让你直接写正文（记忆留到第二步）。
```

`{正文回合指令}`：

```markdown
【正文回合】调研已经结束，现在直接按调研结果、本轮输入和本书设定 / 文笔参考写正文：先在思考通道定大纲，只输出 5 个二级标题（`## 剧情演绎` → `## 推荐行动` → `## 当前时间` → `## 世界状态` → `## 角色状态`）；`## 当前时间` 写本轮**结束**时的剧情内时间，格式沿用历史。第一步**不要**写 `## 记忆总结`，禁止调用历史编辑器（记忆维护留到第二步）。别复述历史、工具结果与本指令。
```

`{维护回合指令}`：

```markdown
[State-maintenance turn] 正文已经写完，现在进入第二步：**只维护记忆总结**。根据正文里的 `## 当前时间`，调用一次 `narrchat_editHistory` 的 `op=append`，追加**恰好一条**本轮记忆条目（`{轮次}` = 本轮轮号的裸数字，`{时间}` = 正文的 `## 当前时间`）。历史栏不接受 `op=noChange`；需要合并时，按下面的合并指令在**同一次调用**里补 `op=set`。本回合不输出正文、不联网、不改世界状态 / 角色状态 / 当前时间。第一步若已读过历史，它的 `<memorySummary>` 结果就在上面，维护步重复读取会被拒绝；第一步漏读时才允许补读一次。
```

`{修复回合指令}`（接在维护回合之后）：

```markdown
[State-maintenance turn] 只修复下面列出的各项，只调工具、不要输出正文。锚点从对话里已有的历史结果块与失败回传的栏目全文中复制，实在定位不到才用 `op=reset` 整栏重写。只维护记忆总结，清单必须做完。
```

维护回合的补充与清单：

- 历史栏里已经有本轮那一条时补一句「注意：历史栏里已经有本轮那一条了，**不要重复追加**；
  只检查格式与合并要求，缺合并就补 `op=set`。」；
- 待修清单由应用按缺口生成，按 历史 → 角色 → 世界 排序、至多 8 条（世界 / 角色的排序是保留
  框架，当前只有历史项）；输出触顶被截断时补一句「把工具调用拆短些」，但**不改**用户设置的
  最大 token；
- 没做完的合并指令：每个区间一条 `op=set`，`before` = 该区间各轮条目原文（用 `\n` 连接，
  从读取结果里逐字复制），`newLine` = 合并行；随后照常 `op=append` 追加本轮条目。

## 五、缓存与成本

顺序即前缀，稳的排前面：

```
system  →  历史（只追加）  →  本轮 user  →  （Agent）回合指令
```

- **system 逐字节稳定**是最大的缓存收益：工具开关一变它就变，这是已知代价（见 system 文档 §十一）；
- **历史原样回放**：上一轮的 assistant 必须一字不改地回放，改一个字符就从那里开始失效；
- **本轮 user 每轮都变**：前置词 / 记忆合并 / 输入都在里面，它变了不影响 system 与历史的命中；
- **回合指令追加在尾部**：同一轮内 system 与工具集不变，Agent 各步共用同一份前缀。

## 七、改版约定

1. 上下文文案与顺序改动：先改本文，再同步 `prompt_v3_context.dart`；
2. 新增成分：先定位置与空块规则（本文 §二），再动实现；
3. 本轮 user 消息只有**一条**：成分按 §二 的顺序合成一条发出，报文层不再拆条；
4. 任何改动都要过一遍"前缀是否还是逐字节稳定"这条线（§五）。
