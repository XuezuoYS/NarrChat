# 用户气泡超长收起（2026-10-13，后改版）

chat 页用户气泡超 7 行自动收起，类 Gemini。

## 形态

- 正文按**完整可用宽**排版，控件不挤占换行宽度（旧版让出 32~50px，正文被挤窄、行数变多）。
- 收起：正文 7 行 + 下方独立一行，左「…」、右下箭头。
- 展开：全文铺开，箭头独占正文下方一行；省略号消失。
- 短消息（≤7 行）无尾行，气泡与从前一致。
- 展开 / 收起时气泡**顶部视觉位置不动**（内容向下展开），无滚动动画。

## 实现

- `lib/widgets/collapsible_content.dart`：通用 `RenderProxyBox`，布局阶段把正文裁到「实测第 N 行下沿」（首帧生效，不需要两帧测量）。只管裁切：全宽排版、不画省略号。
- `lib/widgets/chat_bubble.dart`：`UserBubbleBody` = `CollapsibleContent` + 尾行 `Row[…, Spacer, 箭头]`；AI 气泡不动。

## 折叠阈值

行数按**实际排版**统计（`getBoxesForSelection` 行框数，软换行也算），阈值 = 实测第 N 行字框下沿（段间块间距按比例分摊）。三个「不能」：

- 不能按源码 `\n` 数行（软换行会多折行）。
- 不能用整段排版高度（Markdown 块间距会把阈值切进行中间，半截行照样画出来）。
- 正文宽度必须恒定（宽度变化会让行数跟着变，出现「箭头出现 → 变窄多一行 → 又不用收」的抖动）。

## 展开锁顶部、收起锁底部（消息列是 `reverse: true` 底部锚定）

条目变高 / 变矮时它的**底边**天然不动，顶边往上跑 / 往下滑。两条方向刚好各取所需：

- **展开**：以**顶部**为锚点固定不动 —— 补 Δ（= 正文自然高度 − 裁切阈值）让内容朝
  下方铺开，读者从消息开头往下读（顶边在视口内、外都一样锁）。补偿**不在气泡里
  `jumpTo`**：切换瞬间列表还是旧尺寸，`maxScrollExtent` 没算进新高度，自己夹紧会把
  补偿量吃掉（超长气泡 Δ 数千 px 时能差出几千 px）；改为登记到 `ScrollLockAnchor`，
  由 `ReadingAnchorScrollPhysics` 在**下一帧的布局阶段**（新范围已知、修正走视口重排
  重试循环，无漂移帧）补进偏移。
- **收起**：以**底部**为锚点固定不动 —— 底边锚定是列表的天然行为，**一个偏移都
  不用补**：控件停在指尖 / 光标下，正文朝下收拢。

> 2026-10-14 走过的弯路：曾无条件锁顶边，而点收起时读者通常在气泡尾部（顶边早在
> 视口上方几千 px），锁住看不见的顶边等于把整屏内容平移 Δ（实测近万 px）——
> 就是「一收起就跳到全页顶部」。改成「收起锁底边」后这条链整体消失。

末条气泡（阅读锚定的对象）离底阅读时，锚定会把这次高度变化当成「视口下方长高」
再补一次：展开时会叠成双倍、收起时会破坏「底边不动」，所以按需声明压掉
（`ScrollLockRequest.suppressAnchorGrowth`）。

控件点击判定**不依赖手势竞技场**（见 `_CollapseToggle`）：鼠标拖动阈值只有 1px，
`InkWell.onTap` 会被滚动拖动抢掉，表现为「点一下没反应，点几下才行」。

## 踩坑（下次别踩）

- `context.size` 不能在 build 里读 → 用渲染对象在布局阶段量。
- 布局期读**孙级** `size` 触发 `sizeAccessAllowed` 断言（只有直接子级可读且需 `parentUsesSize: true`）→ 行数用「选区行框数」绕开。
- `RenderParagraph.preferredLineHeight` 是 `@visibleForTesting`，生产不可用。
- **横向参数绝不能进纵向裁剪 / 阈值**：多溢出两行就是把横向留白加进了裁剪高度。绘制裁剪必须严格 = `Offset.zero & size`；尺寸断言抓不到绘制溢出（size 一直是对的），必须盯裁剪框或看像素。
- 测纵向位置用 `CollapsibleContent` 的矩形：`MarkdownPreview` 未被裁切，bottom 比可见区高。
- 列表懒加载会回收滚出视口的条目：测试里滚太远，`find.text(...)` 会突然找不到。
- 别用 PowerShell 的 `-replace` 改含中文的 Dart 文件（编码会写坏）。
